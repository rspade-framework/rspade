NAME
    LibreOffice Integration - document thumbnail rendering via headless soffice

SYNOPSIS
    Config: config('rsx.libreoffice.*')
    Renderer: App\RSpade\Core\Files\Libreoffice_Thumbnail_Renderer
    Registered in: config('rsx.thumbnails.renderers') for Office mime types

DESCRIPTION
    The thumbnail pipeline's "produce a raster from bytes" step is a registry keyed
    by mime type (see `rsx:man thumbnails` / `rsx:man file_upload`). For Office
    documents (Word/Excel/PowerPoint/OpenDocument), that step is handled by
    Libreoffice_Thumbnail_Renderer, which shells out to headless LibreOffice to
    convert the document to PDF and then rasterizes page 1 with Imagick.

    The result flows through the SAME downstream pipeline as image thumbnails:
    same WebP encoding, same content-hash-keyed cache, same quota sweeps, same
    endpoints, same authorization gates. Only the raster-production step differs.

    This integration is GENERIC and framework-level; nothing application-specific
    is involved. Any attachment whose mime type maps to the LibreOffice renderer
    gets document previews automatically, and has_thumbnail() reports true for it.

    ONE SOFFICE POOL, THREE CONSUMERS. The soffice-discovery routine
    (Libreoffice::find_soffice) and the cluster-wide concurrency semaphore are SHARED
    by three callers, so headless LibreOffice has exactly one binary-discovery path and
    one slot pool regardless of what a conversion targets:
      - Libreoffice_Thumbnail_Renderer   Office doc -> PDF -> rasterized thumbnail (here)
      - Libreoffice_Text_Extractor       Office doc -> text, for full-text search
      - File_Preview_Controller          Office doc -> cached PDF rendition, for the
                                         Document_Preview component
    The text extractor and PDF rendition pipeline are documented in
    rsx:man document_search; only their shared soffice mechanics live here.

HOW IT WORKS
    0. The document.thumbnail_render resolve chain runs FIRST, ahead of the renderer
       registry (rsx:man document_search / rsx:man event_hooks): an app #[OnEvent]
       handler may return WebP bytes to take over, ['unsupported'=>true] to force the
       extension icon, or null to decline to the framework registry below.
    1. A thumbnail request resolves the attachment's bytes to a local blob
       (materializing external/handler-backed attachments on demand).
    2. renderer_class_for_mime($mime) matches the blob's mime against
       config('rsx.thumbnails.renderers'); Office mimes map to
       'Libreoffice_Thumbnail_Renderer' (unless the integration is disabled).
    3. The renderer acquires a concurrency slot (see CONCURRENCY), then runs:
           soffice --headless --convert-to pdf --outdir <tmp> <source>
       inside a private per-invocation user profile
       (-env:UserInstallation=file://<tmp>/profile), so concurrent renders never
       collide on a shared LibreOffice profile.
    4. Imagick reads page 1 of the produced PDF and returns the raster handle.
    5. The pipeline resizes/crops/encodes to WebP and caches it.

    FAIL LOUD, SUBSTITUTE IN THE PIPELINE: the renderer THROWS on any failure
    (missing soffice, conversion error, timeout). The thumbnail pipeline catches
    the throw, logs an error line, and serves the generic extension icon instead.
    The substitution lives in the pipeline, never inside the renderer.

ENABLE / DISABLE
    config('rsx.libreoffice.enabled') is the master switch (env LIBREOFFICE_ENABLED,
    default true).

    - Enabled + conversion succeeds  -> real document thumbnail.
    - Enabled + conversion fails      -> error logged, extension icon served.
    - Disabled                        -> Office mimes are treated as having NO
                                         renderer: the extension icon is used
                                         SILENTLY (no soffice call, no log noise),
                                         and has_thumbnail() reports false.

    Disable on nodes where LibreOffice is not installed to avoid error logs:
        LIBREOFFICE_ENABLED=false   (in that node's .env)

CONCURRENCY
    LibreOffice is memory/CPU heavy (a conversion can use 100-300 MB). Simultaneous
    renders are bounded cluster-wide by an RSpade counting semaphore (see
    `rsx:man locks`), sized by config('rsx.libreoffice.max_concurrent') (default 2;
    0 = unlimited). The bound spans processes and containers, so multiple app nodes
    cannot collectively overwhelm a host.

    The semaphore is shared by NAME ('libreoffice_thumbnail' - a historical name that
    literally means "libreoffice slots") across all three soffice consumers
    (thumbnails, text extraction, PDF renditions), so they draw from ONE pool and the
    max_concurrent ceiling bounds total soffice invocations, not per-feature ones. The
    PDF rendition pipeline uses its own hard timeout, config('rsx.preview.rendition_timeout')
    (default 60s), rather than the thumbnail render timeout below.

    If no slot frees within config('rsx.libreoffice.slot_wait_timeout') seconds, the
    render degrades to the extension icon rather than queueing unboundedly.

    KNOWN GRANULARITY LIMIT: the semaphore is served by rsx-lockd and is therefore
    CLUSTER-wide, while soffice concurrency is really a per-box CPU/memory limit. On a
    single-server deployment the two are identical; on a fleet, max_concurrent bounds
    the whole cluster rather than each node. Per-server quotas are part of the
    multi-web-server clustering epic in the backlog, not something to work around here.

TIMEOUT
    Each render is hard-capped at config('rsx.libreoffice.timeout') seconds
    (default 30), measured from the moment the render ACQUIRES its concurrency slot
    and actually starts (not including slot-wait time). A timeout throws, and the
    pipeline serves the icon.

CONFIGURATION
    config/rsx.php -> 'libreoffice':

        enabled            bool    Master switch. Default true (env LIBREOFFICE_ENABLED).
        binary_path        ?string Absolute path to the soffice binary. Default null
                                   (env LIBREOFFICE_BINARY_PATH) = auto-detect on
                                   PATH and common install locations
                                   (/usr/bin/soffice, /usr/local/bin/soffice,
                                   /opt/libreoffice/program/soffice).
        max_concurrent     int     Max simultaneous renders (semaphore). Default 2.
                                   0 = unlimited.
        timeout            int     Per-render hard cap in seconds. Default 30.
        slot_wait_timeout  int     Max seconds to wait for a concurrency slot before
                                   degrading to the icon. Default 30.

    Registration (which mimes use LibreOffice) lives in
    config('rsx.thumbnails.renderers') and is overridable/extendable in
    rsx/resource/config/rsx.php using the same idiom as
    config('rsx.attachments.handlers').

INSTALLING LIBREOFFICE
    RSpade dev Docker images ship LibreOffice preinstalled with sensible defaults
    (auto-detected binary, max_concurrent 2, 30s timeout). To provision another
    environment on Debian/Ubuntu:

        apt-get install -y --no-install-recommends \
            libreoffice-writer libreoffice-calc libreoffice-impress libreoffice-core \
            ghostscript fonts-liberation fonts-dejavu-core

    Notes:
    - ghostscript is required for Imagick to rasterize the intermediate PDF (and for
      direct PDF-attachment thumbnails via Imagick_Thumbnail_Renderer).
    - Install at least one general-purpose font family; without fonts, LibreOffice
      substitutes poorly. Add fonts-noto-cjk etc. for non-Latin content.
    - The process user must be able to write to the system temp dir.
    - Some base images disable PDF reads in ImageMagick policy.xml; allow "read" for
      the PDF coder if PDF thumbnails come out blank.

    See docs.dev/reference/docker_container_additions_7_2_2026.md for the full container
    provisioning writeup.

VERIFYING
        php artisan rsx:test Thumbnail_Renderer_Test --framework

    Includes test_libreoffice_real_render, which converts a document through soffice
    and asserts a raster is returned (auto-skips if soffice is absent).
