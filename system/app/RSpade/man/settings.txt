NAME
    Rsx_Settings - application custom value (settings) store

SYNOPSIS
    use App\RSpade\Core\Settings\Rsx_Settings;

    // Define a setting (usually from a migration)
    Rsx_Settings::define([
        'key'     => 'billing_dow_cutoff',
        'label'   => 'Billing cutoff day of week',
        'type'    => Rsx_Settings::TYPE_INTEGER,
        'scope'   => Rsx_Settings::SCOPE_GLOBAL,
        'default' => 1,
    ]);

    // Read a value in program code
    $cutoff = Rsx_Settings::get('billing_dow_cutoff');   // 1 (int)

    // Set a value (usually from an admin screen)
    Rsx_Settings::set('billing_dow_cutoff', 5);

DESCRIPTION
    Rsx_Settings is a database-backed key/value store for application behaviour
    values: credentials (for example a QuickBooks API key) and operational
    preferences (for example the day of week a billing cycle ends). They are like
    config-file values, but editable at runtime and stored in the database.

    Each setting has a developer-authored DEFINITION (a machine key, a human
    label, a type, a scope, and a default) and a stored VALUE. Definitions are
    registered with define(); values are written with set() and read with get().

    PHP ONLY. These values never auto-populate into JavaScript and are not exposed
    through any generated API. To surface a value to the client, return it
    explicitly from an #[Ajax_Endpoint] method. This is structural: the subsystem
    has no Eloquent model. Its two tables are underscore-prefixed system tables
    (_settings, _setting_values) accessed through the query builder, like
    _migrations and _type_refs, so nothing about them is auto-discovered,
    auto-documented, or reachable through the ORM fetch endpoint.

    Difference from Laravel / RSpade config:
    - config(): static, file-based, version-controlled, NOT runtime-editable.
    - Rsx_Settings: runtime-editable, per-tenant where needed, admin-facing.

VALUE TYPES
    Values are stored serialized in a single column and cast on read:

    Rsx_Settings::TYPE_TEXT       string
    Rsx_Settings::TYPE_INTEGER    int
    Rsx_Settings::TYPE_DECIMAL    string (fixed precision is preserved as a string;
                                  never a float - important for money/rates)
    Rsx_Settings::TYPE_FLOAT      float (stored as a double)
    Rsx_Settings::TYPE_BOOLEAN    bool
    Rsx_Settings::TYPE_DATE       "YYYY-MM-DD" (validated via Rsx_Date)
    Rsx_Settings::TYPE_DATETIME   ISO 8601 string (normalized via Rsx_Time)
    Rsx_Settings::TYPE_JSON       array (json_decode)

    set() validates a value against the declared type and throws on a mismatch.
    Type-specific configuration (for example a decimal scale) can be passed in the
    definition's 'meta' array.

SCOPING
    Rsx_Settings::SCOPE_GLOBAL  one value for the whole installation.
    Rsx_Settings::SCOPE_SITE    one value per tenant (site).

    For a site-scoped setting, get()/set() default the site to the CURRENT
    EXPERIENCE's site - the staff session site on a staff request or in CLI, and the
    site the app declared for the portal (Portal_Session::set_site_id) on a portal
    request, which throws if none was declared. Pass an explicit $site_id to target
    another. A site with no stored value resolves to the definition default. Global
    settings ignore the site entirely.

API REFERENCE
    Rsx_Settings::define(array $def): void
        Register or update a definition. Idempotent. Keys:
          key (required)        machine identifier (unique)
          label (required)      human-readable name
          type (required)       a TYPE_* constant
          scope                 SCOPE_GLOBAL (default) or SCOPE_SITE
          default               default value (type-cast and stored)
          description           free text
          meta                  array of type-specific config
          is_secret             bool; an admin UI should mask it
          group                 string for UI grouping
          sort_order            int

    Rsx_Settings::get(string $key, ?int $site_id = null): mixed
        Resolved, type-cast value: the stored override for the scope, else the
        definition default. Throws if the key is not defined.

    Rsx_Settings::set(string $key, mixed $value, ?int $site_id = null): void
        Validate against the type and persist. Throws if undefined or mistyped.

    Rsx_Settings::forget(string $key, ?int $site_id = null): void
        Remove the stored value, reverting to the definition default.

    Rsx_Settings::is_defined(string $key): bool
        Whether a key has been defined.

    Rsx_Settings::all(?int $site_id = null): array
        All active definitions with their resolved values, for an admin UI. Each
        entry: key, label, description, type, scope, group, is_secret, value.

DEFINING VIA MIGRATIONS
    Application settings are registered from migrations by calling define(). The
    framework migration that creates _settings / _setting_values must already have
    run (it ships with the framework), so an application migration only declares
    its own settings:

        public function up()
        {
            \App\RSpade\Core\Settings\Rsx_Settings::define([
                'key'     => 'quickbooks_api_key',
                'label'   => 'QuickBooks API key',
                'type'    => \App\RSpade\Core\Settings\Rsx_Settings::TYPE_TEXT,
                'is_secret' => true,
                'group'   => 'integrations',
            ]);
        }

    define() is idempotent, so re-running or re-declaring a setting updates the
    definition in place rather than duplicating it.

SECRETS
    Mark credentials with 'is_secret' => true. Values are stored as plain text;
    an admin UI should mask a secret field (show only that it is set) and must not
    echo it back into a page or a JavaScript payload.

EXAMPLES
    // A per-tenant preference, read in code
    Rsx_Settings::define([
        'key' => 'invoice_due_days', 'label' => 'Invoice due (days)',
        'type' => Rsx_Settings::TYPE_INTEGER, 'scope' => Rsx_Settings::SCOPE_SITE,
        'default' => 30,
    ]);
    $due = Rsx_Settings::get('invoice_due_days');     // current site's value or 30

    // A global JSON setting
    Rsx_Settings::define([
        'key' => 'feature_flags', 'label' => 'Feature flags',
        'type' => Rsx_Settings::TYPE_JSON, 'default' => ['beta_ui' => false],
    ]);
    $flags = Rsx_Settings::get('feature_flags');       // ['beta_ui' => false]

    // Surfacing a value to the front end (explicit, never automatic)
    #[Ajax_Endpoint]
    public static function client_config(Request $request, array $params = [])
    {
        return ['invoice_due_days' => Rsx_Settings::get('invoice_due_days')];
    }

NOTES
    - get() on an undefined key throws - settings are expected to be declared.
    - Storing null is distinct from forgetting: a null value is an explicit value;
      forget() removes the row so the default applies again.
    - There is no model, no JS stub, and no ORM fetch access by design.
