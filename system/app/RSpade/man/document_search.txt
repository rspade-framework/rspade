NAME
    document_search - document text extraction, full-text search, and in-browser
    document preview (Document_Preview + pdf.js + PDF renditions)

SYNOPSIS
    Extraction (background, framework-internal):
        config('rsx.search.*')   Search_Index_Service::index_pending  (#[Exclusive] cron)

    Search (app-facing):
        File_Attachment_Model::search_text($query [, $mode])   // Eloquent Builder
        $attachment->get_extracted_text()                      // ?string
        $attachment->get_extraction_status()                   // ?int (null = pending)

    Preview (in-browser):
        <Document_Preview $attachment_id=this.args.id />
        config('rsx.preview.*')   File_Preview_Controller  (/_preview/pdf/:key)

    CLI:
        php artisan rsx:search:reindex --status
        php artisan rsx:search:reindex --all | --failed | --below-version=N
                                       | --storage=ID | --attachment=ID
        php artisan rsx:health         # verifies soffice / poppler / fonts

DESCRIPTION
    RSpade extracts the text of uploaded documents into a FULLTEXT-searchable store
    and renders documents in the browser, both as framework-core features every app
    inherits. Neither requires any app wiring: an upload is queued for extraction
    automatically, and <Document_Preview> renders a PDF/Office/image attachment with
    no per-format branching in the page.

    Both systems key their work on the DEDUPLICATED blob (File_Storage_Model), not on
    the logical attachment. Identical bytes are extracted once and converted to a PDF
    rendition once, no matter how many attachments reference them.

    Unlike Laravel, which ships no document pipeline (you would wire Scout + a driver
    for search and a JS library by hand for preview), RSpade discovers the extractor,
    viewer, and health inventory through the manifest and exposes three #[OnEvent]
    resolve chains so an app can override any stage without touching core.

    The two systems are independent (search does not need preview, and vice versa) but
    share the headless-LibreOffice slot pool (see rsx:man libreoffice) and the same
    binary dependencies.

EXTRACTION PIPELINE
    The queue IS a flag. Every File_Storage_Model blob carries is_indexed:

        is_indexed = 0    queued (never attempted, or re-queued)
        is_indexed = 1    attempted (a _search_indexes row now exists for it)

    There is NO stored PENDING state. The ABSENCE of a _search_indexes row (with
    is_indexed = 0) is the queue. A row is written only AFTER an attempt, so its
    status_id is always one of three terminal outcomes:

        EXTRACTED     text pulled (may be empty - a text-free/all-image PDF is a
                      VALID empty extraction, not a failure; OCR is out of scope).
                      Text over config('rsx.search.max_text_bytes') is TRUNCATED to
                      the cap and RECORDED (row metadata truncated=true +
                      original_bytes) - still EXTRACTED, never a silent partial
        FAILED        an extractor threw a real, RETRYABLE fault (missing binary,
                      non-zero exit, a missing/corrupt source); the error is stored
                      on the row
                      A SCANNED PDF is the case that surprises people: it is
                      application/pdf, so it HAS an extractor, pdftotext runs, and
                      it succeeds - yielding EMPTY text. It records EXTRACTED with
                      no content, NEVER UNSUPPORTED and never FAILED, and it will
                      never match a search. Only a standalone image file (which has
                      no extractor at all) is UNSUPPORTED. There is no OCR.
        UNSUPPORTED   no extractor is registered for the mime (image, zip, ...);
                      LibreOffice is disabled for an Office mime; OR the source is
                      unextractable BY DESIGN (a password-protected / encrypted
                      document) - that reason is stored in the row's error column,
                      because a retry can never help (unlike FAILED)

    Draining. Search_Index_Service::index_pending is #[Exclusive] (at most one pass
    runs cluster-wide) and #[Schedule('*/5 * * * *')]. It processes ONE blob per
    iteration (lowest is_indexed=0 id first) until the queue is empty; each attempt
    sets is_indexed = 1 so work never repeats and the loop terminates. A prompt kick
    (Task::dispatch on blob creation/materialization) drains uploads without waiting
    for the 5-minute cron. Master switch: config('rsx.search.enabled') - when false,
    no kick is fired and the cron is a no-op (existing rows untouched).

    Re-extraction. Bump config('rsx.search.extractor_version') when an extractor
    changes in a way that should re-produce existing text, then:

        php artisan rsx:search:reindex --below-version=N

    re-queues every blob indexed by an older generation (sets is_indexed = 0). The
    cron/kick re-extracts them one at a time.

    Office documents route by FAMILY inside Libreoffice_Text_Extractor, because no
    single LibreOffice filter covers them all:

        Writer   (doc/docx/odt/rtf/...)  --convert-to 'txt:Text (encoded):UTF8'
        Calc     (xls/xlsx/ods/...)      --convert-to fods (flat XML, ONE file, ALL
                                         sheets), then a STREAMING XMLReader pass
                                         emits each sheet's name + every cell's text
        Impress  (ppt/pptx/odp/...)      --convert-to fodp (flat XML), same pass over
                                         each slide's text

    The 'Text (encoded)' filter is Writer-ONLY: it silently produces NO output for a
    Calc or Impress document (so every spreadsheet/presentation used to FAIL). The
    flat-XML route is streamed (never DOM-loaded) so a 170-sheet workbook does not
    blow memory - the reader stops once assembled text passes the byte cap and the
    service truncates precisely (see the truncation note above).

    Dedup and site scoping. _search_indexes rows are keyed on File_Storage_Model
    (indexable_type = 'File_Storage_Model', indexable_id = the blob id) and carry NO
    site_id - extraction is cross-site because the deduplicated blob is cross-site.
    Site scoping happens at the ATTACHMENT join: search_text() returns a
    File_Attachment_Model builder the app constrains with its own site/permission
    filters.

    External / OneDrive residency. When bytes live in an external system (the
    attachment-handler seam, rsx:man file_upload), the blob is only queued once it is
    MATERIALIZED (store_blob() flips is_indexed on and kicks the drain). Until then the
    attachment has no resident blob and get_extraction_status() reports null (pending)
    WITHOUT forcing a materialization. An app that wants text sooner can either force
    materialization or intercept document.extract_text (below).

FILTER CHAINS (the app extension surface)
    Three Rsx::trigger_resolve() chains let an app override or extend a document stage
    without editing core. trigger_resolve semantics: handlers run in priority order,
    each receiving the SAME payload; the FIRST to return a non-null value WINS and the
    chain stops; if every handler returns null (declines), the framework runs its own
    terminal default. See rsx:man event_hooks (RESOLVE EVENTS).

    document.extract_text  (Search_Index_Service::extract_storage)
        Payload:  ['storage' => File_Storage_Model, 'path' => string, 'mime' => string]
        Return:
            null                                decline -> framework extractor registry
            string                              the extracted text  (-> EXTRACTED)
            ['status' => 'unsupported', 'error' => ?string]   (-> UNSUPPORTED)
            ['status' => 'failed', 'error' => string]         (-> FAILED)
            (anything else fails loud)

            #[OnEvent('document.extract_text')]
            public static function extract_special($data) {
                if ($data['mime'] !== 'application/x-special') return null; // decline
                return Special_Lib::to_text($data['path']);                 // extracted
            }

    document.preview_rendition  (File_Preview_Controller::pdf_rendition)
        Runs AFTER the authorization gates (below). Overrides how an attachment becomes
        a PDF rendition for pdf.js.
        Payload:  ['attachment' => File_Attachment_Model, 'request' => Request]
        Return:
            null                       decline -> framework rendition pipeline
            Response                   takeover - the handler serves the response
            ['path' => <abs pdf>]      the framework serves that PDF file inline
            ['unsupported' => true]    415 - no PDF rendition for this attachment
            (anything else fails loud)

            #[OnEvent('document.preview_rendition')]
            public static function convert_cad($data) {
                if ($data['attachment']->file_extension !== 'dwg') return null; // decline
                return ['path' => Cad_Service::to_pdf($data['attachment'])];    // serve
            }

    document.thumbnail_render  (File_Attachment_Controller::_render_thumbnail_data)
        Sits at the TOP of the thumbnail pipeline, ahead of the renderer registry
        (rsx:man libreoffice, rsx:man thumbnails). Overrides the "bytes -> raster" step.
        Payload:  ['attachment' => File_Attachment_Model, 'path' => string,
                   'type' => string, 'width' => int, 'height' => ?int]
        Return:
            null                       decline -> framework renderer registry
            string                     WebP bytes, served as-is
            ['unsupported' => true]    render the generic extension icon
            (anything else fails loud)

            #[OnEvent('document.thumbnail_render')]
            public static function preview_service($data) {
                if (!My_Preview::handles($data['attachment'])) return null;    // decline
                return My_Preview::webp($data['attachment'], $data['width']);  // bytes
            }

SEARCH API
    File_Attachment_Model::search_text(string $query, string $mode = 'BOOLEAN')
        Returns an Eloquent Builder of attachments whose extracted text matches $query.
        Runs a FULLTEXT MATCH...AGAINST over _search_indexes (EXTRACTED rows only),
        then constrains a File_Attachment_Model query to the matching blobs. $mode is
        'BOOLEAN' (default, supports +term -term "phrase") or 'NATURAL LANGUAGE'. The
        app composes site scoping, joins, and ordering onto the returned builder:

            $rows = File_Attachment_Model::search_text('+contract -draft')
                ->where('site_id', Session::get_site_id())
                ->orderByDesc('created_at')
                ->get();

        Dedup note: one matching blob may back several attachments, so the builder can
        yield multiple rows per blob - exactly what a staff-wide Files index wants.

    $attachment->get_extracted_text(): ?string
        The extracted text, or null if the blob has not been indexed yet. Routes
        through resolve_storage() (materializes external bytes if needed). Returns ''
        for an indexed blob that yielded no text (FAILED / UNSUPPORTED / text-free) -
        use get_extraction_status() to distinguish.

    $attachment->get_extraction_status(): ?int
        The Search_Index_Model::STATUS_* id, or null if pending. Reads file_storage_id
        directly and NEVER materializes external bytes (a non-resident attachment reads
        as pending).

    File_Storage_Model->get_search_index(): ?Search_Index_Model
        The raw index row for a blob (content, status_id, error, extraction_method,
        extractor_version, metadata), or null if never attempted.

DOCUMENT_PREVIEW COMPONENT
    <Document_Preview> renders a real, in-browser preview of an attachment by resolving
    a viewer component from the server (File_Preview_Controller::get_preview_info) and
    dispatching to it - no per-format branching in the page.

        <Document_Preview $attachment_id=this.args.id />
        <Document_Preview $attachment_id=42 $page=3 $width=600 $height=800 />

    Args:
        $attachment_id  (required) File_Attachment_Model id. Throws if absent.
        $page           (optional) initial page for paged viewers (default 1).
        $width/$height  (optional) fixed px; omitted -> fills the container (100%).

    Events OUT (re-emitted from the active viewer; listen on the Document_Preview):
        'preview_loaded' {pages, width, height, ratio}
        'page_changed'   {page}

        The load event is 'preview_loaded', NOT 'loaded' - 'loaded' is a reserved
        jqhtml lifecycle event fired internally with no payload, so a custom event may
        never reuse it (nor create/load/ready/render/stop). See rsx:man jqhtml.

    Methods (delegate to the active viewer; no-op before it is ready):
        set_page(n) / get_page() / get_pages()

    Preview-unavailable state. An attachment degraded at upload (an image whose bytes
    could not be parsed - see rsx:man file_upload, UNPARSEABLE IMAGE DEGRADE) carries
    preview_unavailable=true. get_preview_info() surfaces the flag and <Document_Preview>
    renders a "Preview unavailable" state instead of a viewer (pipeline_mime() is
    application/octet-stream, so it would resolve to Icon_Viewer regardless).

    Viewer registry. get_preview_info() resolves the viewer by mime via
    config('rsx.preview.viewers') (an ordered fnmatch map of mime glob -> viewer
    component simple name; first match wins). The framework ships three viewers and a
    terminal '*' entry so every mime resolves:

        Pdf_Viewer     PDFs and (via rendition) convertible Office docs. Lazy-loads
                       pdf.js and paginates on a canvas.
        Image_Viewer   image/*  (natural-dimension preview).
        Icon_Viewer    terminal - the generic extension icon for anything else.

    An app adds or overrides viewers by merging config('rsx.preview.viewers') in
    rsx/resource/config/rsx.php. A built-in viewer is rendered directly by the
    Document_Preview template; an APP-registered viewer name is instantiated
    dynamically into the host element in on_ready with {url, extension, file_name,
    page}.

SERVER SURFACES
    GET /_preview/pdf/:key   (File_Preview_Controller::pdf_rendition)
        The PDF that pdf.js loads. DUAL authorization gate cascade - a rendition
        exposes the full document, so BOTH file.thumbnail.authorize AND
        file.download.authorize must return true (identical to inline()/download).
        After auth, the document.preview_rendition chain may override. Framework
        default: a PDF blob is served as-is; a convertible Office mime
        (config('rsx.preview.convertible')) with LibreOffice enabled is converted to a
        cached PDF at storage/rsx-renditions/{blob-hash}.pdf (content-addressed, so
        identical bytes convert once); anything else is 415. Served inline with an
        immutable one-year cache.

    POST get_preview_info  (#[Ajax_Endpoint])
        Server-side viewer resolution consumed by <Document_Preview>: returns
        {viewer, mime, file_name, extension, urls:{rendition, inline, icon}}. Gated by
        file.thumbnail.authorize only (metadata, not full content). No config is
        exported to the client - resolution is server-side.

    GET /_preview/pdfjs.mjs, GET /_preview/pdf_worker.mjs
        Stream the pdf.js module + worker bytes from the committed system/node_modules
        (pdfjs-dist), text/javascript, one-year cache. pdf.js is NEVER bundled: the
        Pdf_Viewer lazy-loads it from these routes with ?v={build_key} on first use and
        memoizes it class-wide. The dynamic import is routed through
        new Function('u','return import(u)') so the iife bundler leaves the native
        import() untouched (a bare import() would be rewritten to require()).

    The rendition cache is LRU-evicted to config('rsx.preview.quota_max_bytes') by
    File_Rendition_Service::cleanup_renditions (every 30 minutes); each cache hit is
    touch()'d so hot renditions survive.

CONFIGURATION
    config/rsx.php -> 'search' (extraction / full-text):
        enabled                bool    Master switch (env SEARCH_ENABLED). Default true.
        extractor_version      int     Pipeline generation. Bump + reindex --below-version
                                       to re-extract older rows. Default 2 (bumped from 1
                                       for the spreadsheet/presentation extraction fix).
        extractors             array   Ordered fnmatch map: mime glob -> extractor class
                                       (simple, manifest-resolved). First match wins; no
                                       match -> UNSUPPORTED. Overridable/extendable in
                                       rsx/resource/config/rsx.php. Ships:
                                         application/pdf              -> Pdftotext_Text_Extractor
                                         application/msword, ms-excel,
                                         ms-powerpoint, openxml*, opendocument*,
                                         application/rtf              -> Libreoffice_Text_Extractor
                                         text/*, application/csv,
                                         application/json             -> Plain_Text_Extractor
        pdftotext_binary_path  ?string poppler pdftotext path (env). null = auto-detect.
        timeout                int     Per-extractor-invocation cap (seconds). Default 30.
        max_text_bytes         int     Extracted text is capped at this many bytes.
                                       Over-cap extraction is TRUNCATED to the cap and
                                       RECORDED on the row (metadata truncated=true +
                                       original_bytes), never FAILED and never silently
                                       dropped - a partial index stays discoverable.
                                       Default 2 MB.

    config/rsx.php -> 'preview' (Document_Preview / rendition):
        viewers                array   Ordered fnmatch map: mime glob -> viewer component.
                                       First match wins; the trailing '*' -> Icon_Viewer
                                       is terminal. Overridable in the app config.
        convertible            array   Mimes the rendition endpoint converts to PDF via
                                       headless LibreOffice (fnmatch globs). Only
                                       converted when rsx.libreoffice.enabled; else 415.
        quota_max_bytes        int     LRU cap on storage/rsx-renditions. Default 200 MB.
        rendition_timeout      int     Cap (seconds) on one soffice->PDF conversion,
                                       from slot acquisition. Default 60.

    The LibreOffice slot pool, binary path, and concurrency are config('rsx.libreoffice.*')
    (rsx:man libreoffice) - shared by text extraction, PDF renditions, and thumbnails.

BINARY DEPENDENCIES
    The pipeline shells out to external binaries. Provision on Debian/Ubuntu:

        apt-get install -y --no-install-recommends \
            libreoffice poppler-utils fonts-liberation fonts-dejavu-core

    - poppler-utils (pdftotext) backs PDF text extraction.
    - headless LibreOffice (soffice) backs Office text extraction AND Office->PDF
      renditions AND Office thumbnails (one shared soffice slot pool).
    - fonts: without at least one general font family soffice substitutes poorly. Add
      fonts-noto-cjk etc. for non-Latin content.

    rsx:health verifies all of these (LibreOffice, poppler-utils, and the search-index
    backlog) - run it as a container-readiness gate. See rsx:man health.

REINDEX COMMAND
    php artisan rsx:search:reindex <selector>   (exactly one selector; fails loud otherwise)

        --status               report index counts only (no re-queue): total blobs,
                               queued vs indexed, by-status breakdown, extractor-version
                               histogram, enabled flag, current version.
        --all                  re-queue every blob
        --failed               re-queue blobs whose last extraction FAILED
        --below-version=N      re-queue blobs indexed by a generation older than N
        --storage=ID           re-queue one blob by _file_storage id
        --attachment=ID        re-queue the blob backing one attachment
                               (materializes external bytes first)

    Re-queuing is uniform: it sets is_indexed = 0 on the resolved blobs and dispatches
    Search_Index_Service::index_pending; the cron/kick then re-extracts one at a time.

DEMO
    /dev/document_preview - a template SPA page that previews the seeded sample
    documents (a multi-page PDF and an Office doc) through <Document_Preview>,
    exercising pagination and the extracted-text surface. Run it with:

        php artisan rsx:debug /dev/document_preview --user=1

RSX VS LARAVEL
    Search:
        Laravel: install Scout + a driver, define searchable(), run a queue worker.
        RSX:     upload is auto-queued; search_text() returns a Builder; FULLTEXT is
                 built in on the dedup store.
    Preview:
        Laravel: wire a JS PDF library and a server raster route per format by hand.
        RSX:     <Document_Preview $attachment_id=...> resolves the viewer server-side;
                 pdf.js is lazy-served from node_modules, never bundled.
    Extension:
        Laravel: subclass drivers / swap service bindings.
        RSX:     one #[OnEvent] resolve handler per stage (extract / rendition /
                 thumbnail), first non-null wins.

TROUBLESHOOTING
    Text never appears for a document
        Check get_extraction_status(): null = still pending (is the cron/worker
        running? rsx:health "Task Scheduler Liveness"). FAILED = read the row's error
        (rsx:search:reindex --failed after fixing the binary). UNSUPPORTED = no
        extractor for that mime, LibreOffice disabled, or the document is
        password-protected/encrypted (the row's error names the reason - a reindex
        will not help, it is unextractable by design).

    Office docs extract/convert but PDFs do not (or vice versa)
        Different binaries: PDFs need poppler-utils (pdftotext); Office needs soffice.
        rsx:health reports each independently.

    Preview pane is blank / a PDF will not load
        Confirm /_preview/pdfjs.mjs returns 200 (pdfjs-dist installed under
        system/node_modules) and that the dual auth gates allow /_preview/pdf/:key.

    A convertible document returns 415 from /_preview/pdf/:key
        LibreOffice is disabled (config('rsx.libreoffice.enabled')) or the mime is not
        in config('rsx.preview.convertible').
