DEV-MODE .ENV HOSTNAME GUARD (FAIL-LOUD ON MISMATCH)
Date: 2026-07-16

SUMMARY
    Development mode gained a new web-request tripwire: if your .env declares a
    hostname (REALTIME_PUBLIC_URL, RSX_HOSTNAME, or APP_URL) that differs from the
    host the site is actually browsed under, the request now FATALS loudly instead
    of silently misbehaving. This is a Category 2 change: the code lives entirely
    in /system/ core and arrives automatically via the submodule, but on the next
    pull a downstream box carrying a latent .env hostname mismatch will START
    failing loudly - which is the feature, not a regression.

THE CHANGE
    New class: App\RSpade\Core\Env\Rsx_Env_Hostname_Guard, called once per web
    request from Dispatcher::dispatch() (before the portal delegation, so portal
    requests are covered too).

    In development mode only (RSX_MODE=development), every web request compares the
    browsed request host against the hosts embedded in .env:

      - REALTIME_PUBLIC_URL  (only when REALTIME_ENABLED is truthy; exact match)
      - RSX_HOSTNAME         (exact, OR request host ends with ".RSX_HOSTNAME" -
                              the same suffix rule production already uses)
      - APP_URL              (host parsed out; exact match)

    On the first mismatch it throws a fatal RuntimeException naming the variable,
    the declared host, and the request host, e.g.:

      Dev-mode .env hostname mismatch: REALTIME_PUBLIC_URL host
      "app3.dev.example.com" != request host "app.dev.example.com". ...
      fix .env (or RSX_HOSTNAME) to match. [rsx:man realtime]

    Motivating incident: a pasted REALTIME_PUBLIC_URL pointed at ANOTHER instance's
    relay. Both hostnames resolved to the same outer proxy, so the websocket
    connected (state "connected") to the wrong box - realtime silently delivered
    nothing while every signal looked healthy. This guard turns that silent class
    of misconfiguration into an immediate, actionable error.

    Exemptions (these keep working untouched):
      - CLI and non-development modes are skipped entirely.
      - Loopback request hosts (localhost / 127.* / ::1 - the curl / rsx:debug
        testing channel) never trip the guard.
      - .env vars left at a loopback default (Laravel's APP_URL=http://localhost)
        are treated as "not meaningfully set" and skipped.
      - A non-empty but unparseable REALTIME_PUBLIC_URL fatals (malformed URL in
        dev deserves fail-loud) - fix it to a real wss://host/ws value.

    Full reference: php artisan rsx:man realtime (dev-mode hostname guard).

THE FIX
    All of the above lives in /system/ core and reaches you via the submodule
    merge on the next `php artisan rsx:framework:pull`. There is nothing to copy
    into your own /rsx/ code.

ACTION REQUIRED
    Verify your development .env is internally consistent BEFORE your next pull, so
    the newly-loud guard does not surprise you:

    1. Confirm the host you browse the dev site under matches your .env. Check that
       these all agree on the hostname (where set):

           grep -E "^(REALTIME_PUBLIC_URL|REALTIME_ENABLED|RSX_HOSTNAME|APP_URL)=" .env

       If REALTIME_ENABLED is true, the host inside REALTIME_PUBLIC_URL must equal
       the host you browse under. RSX_HOSTNAME may be the exact host or a parent
       domain of it. APP_URL's host (if not http://localhost) must match exactly.

    2. If you provision dev containers by copying a template .env, this is the
       exact copy-paste drift the guard catches: make sure each new box's
       hostname-bearing vars were updated for that box, not left pointing at the
       source instance.

    3. Nothing to change if your dev box browses on localhost, or if your only
       hostname-bearing var is APP_URL=http://localhost - loopback is always exempt.

VERIFICATION
    In development mode, browse your dev site under its real hostname: it should
    render normally. A deliberately wrong Host header should fatal with the message
    above:

        curl -s -H "Host: wrong-instance.example" http://localhost/login | head

    (Loopback requests via plain http://localhost stay exempt and always render.)
