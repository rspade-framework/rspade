TEST-RUN FILE-STORAGE ISOLATION (CORE FIX)
Date: 2026-07-21

SUMMARY
    rsx:test already swaps the DATABASE to rspade_test, but the file subsystem's on-disk
    directories (the content-addressed blob store, the thumbnail cache, and the rendition
    cache) were ONE set of directories shared by every database on the box. That is a
    test-isolation hole: a model-layer attachment delete on the TEST database fires the
    deleted-hook, which unlinks the shared disk file when it was the test DB's last
    reference - destroying a DEVELOPER-database blob whose bytes exist in both (proven
    2026-07-21; the two seeded sample documents were deleted out from under the dev DB by
    a test-side flow). The same hazard exists on every downstream box: an app test deleting
    an attachment whose bytes match a dev attachment nukes the dev file.

    The fix relocates the ENTIRE file subsystem to a test-scoped directory for the duration
    of a test run - a mirror of the DB swap. This arrives via the submodule and is fully
    automatic: your test runs relocate themselves, and normal (non-test) file paths are
    byte-identical to before. There is NO downstream action beyond pulling.

THE CHANGE
    1. New choke point: App\RSpade\Core\Files\Rsx_File_Paths (all static).
           storage_root()      config('rsx.files.storage_root') when set, else storage_path()
           blob_root()         storage_root().'/storage/files'
           thumbnails_root()   storage_root().'/rsx-thumbnails'
           renditions_root()   storage_root().'/rsx-renditions'
       INVARIANT: every file-subsystem disk path now resolves through this class. In
       default mode the paths are byte-identical to the historic storage_path('...') layout.

    2. New internal config key rsx.files.storage_root (config/rsx.php 'files' block),
       default null. Runner-set only; normal deployments never set it.

    3. rsx:test sets rsx.files.storage_root to storage/rsx-tmp/test-storage for the run and
       passes it to the migrate-provisioning subprocess via `migrate --rsx-storage-root`
       (a new INTERNAL option on the migrate command), so even a data-seed migration that
       writes blobs (the template app's import_sample_documents) stays inside the isolated
       root. The test root persists across runs like the migration dump cache and is wiped
       by rsx:clean.

    All blob/thumbnail/rendition call sites in File_Storage_Model, File_Attachment_Controller,
    File_Thumbnail_Service, File_Rendition_Service, File_Preview_Controller, and
    Thumbnails_Clean_Command were rewired through Rsx_File_Paths. The rsx:health storage
    check still reports on the REAL directories (it describes the live environment, not a run).

THE FIX
    Lives entirely in /system/ core and reaches you via the submodule - nothing to copy.
    This document exists so downstream maintainers know the invariant when WRITING new
    file-subsystem code, and understand why their test runs now write under
    storage/rsx-tmp/test-storage.

ACTION REQUIRED
    None to adopt the fix - it is automatic on pull. Your existing tests keep working and
    their file writes/deletes silently relocate off the shared store.

    ONE standing rule when you WRITE framework-or-app code that touches blob, thumbnail, or
    rendition files: resolve the path through Rsx_File_Paths (blob_root() / thumbnails_root()
    / renditions_root()), NEVER storage_path('storage/files' | 'rsx-thumbnails' |
    'rsx-renditions') directly. A raw storage_path() call for those trees reopens this hole -
    a test would again write/delete inside your live store. (If a test hardcoded one of those
    real paths in an assertion, it will now observe the test-scoped path during a run; assert
    through Rsx_File_Paths instead.)

    Mark this change fulfilled once your team is aware of the invariant:

        php artisan rsx:framework:upstream_changes:mark test_storage_isolation_07_21 --fulfilled

VERIFICATION
    - Default mode: Rsx_File_Paths::blob_root() === storage_path('storage/files') (and the
      thumbnail/rendition equivalents) - normal file paths are unchanged.
    - Inside a run: a blob authored by a test lands under storage/rsx-tmp/test-storage and
      NOT the real store; deleting the attachment removes only the test-root file.
    - A full `php artisan rsx:test --framework` run (including a --fresh rebuild that re-runs
      the seed migrations in the provisioning subprocess) leaves the real blob store's file
      inventory unchanged (empty before/after diff).
    - Coverage: tests/storage_isolation (php).
