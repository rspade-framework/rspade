FIX: User_Model::can_admin_role() ALWAYS RETURNED false
Date: 2026-07-29

SUMMARY
    User_Model::can_admin_role(int $role_id) - the framework's privilege-
    escalation guard for user administration - was permanently broken and always
    returned false. A one-character typo read the wrong property:

        $can_admin = $this->role_id_can_admin_roles ?? [];   // WRONG (single _)

    role_id_can_admin_roles (single underscore) is not an enum property, column,
    or relationship, so it fell through Eloquent's __get() to null; `?? []` then
    yielded an empty array and in_array($role_id, [], true) was always false.

    The guard is supposed to return true iff $role_id is in the current user's
    role's `can_admin_roles` enum list - i.e. "may this user administer users of
    that role?" With the bug it denied every role for every user, including
    ROLE_DEVELOPER (100).

    This is FAIL-CLOSED (it over-denies, never over-grants), so it is not an
    exploitable escalation hole - but it silently disabled a documented,
    security-relevant guard: any server-side check built on can_admin_role()
    (delete-user, change-role, grant-permission gates - see `rsx:man acls`
    examples) rejected everyone. The JS mirror (Permission.can_admin_role) used
    the correct property and worked, so client UI showed affordances the PHP side
    then always refused.

THE CHANGE
    Core fix, User_Model.php:314 - the property name now uses the BEM-style
    double underscore the enum getter actually resolves:

        $can_admin = $this->role_id__can_admin_roles ?? [];   // FIXED (double __)

    Both the model method and the static facade Permission::can_admin_role() now
    enforce the `can_admin_roles` hierarchy as documented.

THE FIX
    If you use the framework-core User_Model unchanged, this fix arrives
    automatically via `rsx:framework:pull` - there is nothing to do.

ACTION REQUIRED (only if you OVERRODE User_Model via the class-override pattern)
    If your app copy-replaced User_Model (rsx/models/user_model.php or wherever
    your override lives), your copy carries the same typo. Apply the identical
    change in your override:

        grep -n "role_id_can_admin_roles" rsx/models/user_model.php

    Change any single-underscore `role_id_can_admin_roles` to the double-
    underscore `role_id__can_admin_roles`. (Also check any other place your code
    reads that property - the correct spelling everywhere is the BEM double
    underscore: $user->role_id__can_admin_roles.)

VERIFICATION
    A user whose role defines `can_admin_roles => [400, 500, 600, 700, 800]`
    (e.g. ROLE_SITE_OWNER, 300) should now satisfy:

        $user->can_admin_role(400) === true    // a role below - allowed
        $user->can_admin_role(300) === false   // a peer role - denied
        $user->can_admin_role(200) === false   // a higher role - denied

    Confirm your role-admin screens (assign role, delete user, grant permission)
    now permit the actions your role hierarchy intends, instead of rejecting all.
