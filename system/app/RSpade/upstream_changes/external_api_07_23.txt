EXTERNAL REST API (Core/Api reworked in place)
Date: 2026-07-23

SUMMARY
    The half-built Core/Api subsystem was reworked in place into a complete
    external REST API: attribute-declared endpoints (#[Api_Endpoint] +
    #[Api_Param]) on Rsx_Api_Controller_Abstract, a dedicated Api_Dispatcher that
    authenticates a Bearer key into a COOKIE-LESS headless Session identity,
    declarative param validation, a BARE-JSON response contract (no envelope),
    URL versioning with a catalog display rule, a login-gated /apidocs docs+tester
    page plus an LLM-readable /apidocs/catalog, per-request logging with a daily
    cleanup task, and template-app CRUD controllers for contacts and clients.

    This is primarily a Category 2 change: the engine lives entirely in /system/
    core and arrives automatically via the submodule. But it (a) changes API
    CONTRACTS that any downstream app already using the pre-epic half-built API
    relied on, (b) ships two migrations that run on your next migrate, and (c)
    adds new /rsx/ TEMPLATE files a template-fork consumer will want to copy. All
    three demand downstream action; hence this document.

THE CHANGE
    Per CRITICAL DIRECTIVE #1 (no dual implementations), the prior half-built API
    was REWORKED, not supplemented. What existed before: Api_Key_Model + a working
    Settings > API Keys screen, an #[Api_Endpoint] scan, an
    Rsx_Api_Controller_Abstract that did its OWN Bearer auth in pre_dispatch, an
    Rsx_Api catalog helper, one template contacts controller, and dead
    ApiHandler/API.php. Two latent bugs were in it: the pre_dispatch auth called
    Session::set_login_user_id() (which in web mode CREATED a _sessions row +
    cookie), and Api_Key_Model::get_user() used a site-scoped lookup that returned
    null pre-auth.

    What ships now (all in /system/ core, arriving via the submodule):
    - Api_Dispatcher branches off the main dispatcher for /api/vN/... URLs. Auth
      runs FIRST (uniform 401 pre-route), establishing a headless identity via
      the new Session::_set_api_identity() seam - NO cookie, NO _sessions row, NO
      Set-Cookie ever. The old pre_dispatch auth is GONE.
    - #[Api_Param] is the single source of validation AND docs. Docblock
      @api-param parsing is DELETED.
    - Scan-time enforcement: /api/vN prefix, GET/POST only, base-class lineage,
      every :token declared, unique names, required-vs-default contradiction,
      scalar types only, and no conflict with #[Route]/#[SPA]/#[Ajax_Endpoint]/
      #[FPC]. The converse guard rejects a non-API #[Route] or SPA route under
      /api/vN/.
    - Bare-JSON responses with real status codes; error shape
      {"error":{"code","message","fields"?}}. Rsx_Api gains a response-helper
      family (created/no_content/not_found/unauthorized/forbidden/
      validation_error/error).
    - Api_Catalog (new) owns the version display rule; the catalog methods moved
      OFF Rsx_Api.
    - Api_Request_Log_Model + _api_request_log logging; Api_Cleanup_Service
      prunes on a daily schedule. Api_Exception_Handler (priority 25) renders API
      500s as JSON. Dead ApiHandler.php and API.php were DELETED.

MIGRATIONS (run automatically on your next migrate)
    Two forward-only framework-core migrations ship and run when you migrate
    after pulling:
        2026_07_22_144452_add_scopes_to_api_keys.php
            ALTER TABLE _api_keys ADD COLUMN scopes TEXT NULL  (reserved; unused)
        2026_07_22_144455_create_api_request_log_table.php
            CREATE TABLE _api_request_log (verb, path, handler, status,
            duration_ms, ip, nullable api_key_id/user_id/site_id, timestamps;
            indexes on created_at/api_key_id/site_id)
    No action beyond running migrate; both are _-prefixed system tables.

ACTION REQUIRED
    Only if your app already built on the pre-epic half-built API. If you never
    touched Core/Api, there is nothing to fix and you simply inherit the feature.

    1. BREAKING - controller auth. If any of your API controllers relied on
       Rsx_Api_Controller_Abstract doing auth in pre_dispatch (or overrode that
       pre_dispatch to layer on auth), REMOVE that. The dispatcher now
       authenticates the Bearer key before your controller runs. Your
       pre_dispatch is still honored for per-controller checks, but it must NOT
       call Session::set_login_user_id()/set_site_id() - those THROW in API mode
       now (the identity is immutable). Read Session:: normally; it reports the
       key's user + site.

    2. BREAKING - catalog helper moved. Any call to
       Rsx_Api::get_endpoint_index() (or the old get_endpoint_detail()) must move
       to Api_Catalog:: (get_endpoint_list / resolve_for_version /
       get_llm_catalog / get_versions). The catalog logic is no longer on Rsx_Api.

    3. BREAKING - response envelope removed. If any client or code relied on the
       old {"success":true,"data":...} / {"success":false,"error":...} envelope,
       update it. Responses are now BARE JSON with real HTTP status codes; errors
       are {"error":{"code","message","fields"?}} at a 4xx/5xx status. Return a
       model/array directly, null for 204, or an Rsx_Api:: helper.

    4. RECOMMENDED - adopt #[Api_Param]. The @api-param DOCBLOCK form is gone.
       Convert each endpoint's params to repeatable #[Api_Param('name', type:
       ..., required: ..., default: ..., description: ..., example: ...)]
       attributes. GOTCHA: never use a class constant in an attribute argument
       (e.g. default: My_Model::STATUS_ACTIVE) - reflection resolves it before
       the autoloader is ready and the scan dies. Use a literal.

    5. CONFIG - the retention knob. config('rsx.api.log_retention_days') (default
       30) controls _api_request_log pruning. It is a CONFIG value, not an env
       var. Override it in rsx/resource/config/rsx.php if 30 days is wrong for
       you; do not add an env key.

    6. RESERVED, DO NOT RELY ON. _api_keys.user_role_id (per-key role override)
       and _api_keys.scopes are present but NOT enforced in v1. A key runs at the
       user's real role and is not scope-limited. Do not use either as a security
       boundary yet.

TEMPLATE FILES (template-fork consumers only)
    These new /rsx/ files ship with the template. If you forked the template and
    want the reference API + docs page, copy them into your fork (they are the
    working pattern; adapt to your own models):

        /rsx/app/api/v1/contacts_api_controller.php   5 endpoints (list/get/
        /rsx/app/api/v1/clients_api_controller.php     create/update/delete)
        /rsx/app/api/CLAUDE.md                        module doc (patterns)
        /rsx/app/apidocs/                             the login-gated /apidocs
            apidocs_spa_controller.php                 docs+tester SPA (a thin
            apidocs_bundle.php                         template module mounting
            Apidocs_Layout.js/.jqhtml/.scss            framework-core components
            Apidocs_Action.js/.jqhtml/.scss            from Core/Api/components/)

    The docs UI COMPONENTS themselves are framework-core (Core/Api/components/)
    and arrive via the submodule; the /rsx/apidocs module is just the standalone
    mount point + bundle, following the Login_Bundle standalone-layout precedent.
    If you do not want a public API you can skip all of the above - the core
    engine is inert until you declare an #[Api_Endpoint].

VERIFICATION
    - php artisan migrate runs the two migrations cleanly; _api_request_log and
      _api_keys.scopes exist.
    - Mint a key (Settings > API Keys), then:
          curl -i https://<APP_URL host>/api/v1/contacts            -> 401 (no key)
          curl -H "Authorization: Bearer rsk_..." <host>/api/v1/contacts -> 200 bare JSON
      and confirm NEITHER response carries a Set-Cookie header, and the _sessions
      row count is unchanged.
    - php artisan rsx:test --framework --filter=Api is green.
    - /apidocs renders (logged-in staff) and /apidocs/catalog returns JSON.
    - php artisan rsx:man external_api documents the full surface.

    Mark this change fulfilled once your API code + .env/config are reconciled:

        php artisan rsx:framework:upstream_changes:mark external_api_07_23 --fulfilled
