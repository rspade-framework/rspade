FRAMEWORK SELF-UPDATE REWORK (vendored topology + marker-based tamper gate)
Date: 2026-07-28

SUMMARY
    The framework update system was rebuilt. The framework core (system/) is no
    longer a git submodule of rspade_system - it is now VENDORED into your app
    repo as ordinary tracked files. `php artisan rsx:framework:pull` no longer
    merges; it clones the distribution, hard-syncs the framework-owned zones,
    three-way-reconciles the rest, and leaves the result as working-tree changes
    for you to review and commit. A marker-based tamper gate replaces the old
    regex/retry machinery. This affects every downstream app: there is a one-time
    conversion, and a few local habits change.

THE CHANGE (why)
    The old updater merged upstream into the system/ submodule. It failed
    routinely because the framework legitimately mutates its own tracked files at
    runtime (Php_Fixer use-header rewrites, class-override .php.upstream renames,
    model_codegen docblock regen, composer classmap regen). Its only defense was
    a bash regex heuristic plus a retry loop, so downstream developers ended up
    hand-running `merge --abort && reset --hard && clean -fd && pull` on nearly
    every update, and framework history never entered the app repo (the gitlink
    reset ritual discarded it). Field reports confirmed the merge path was
    effectively unusable.

    The rework removes the failure mode BY CONSTRUCTION:
      - system/ is vendored (tracked files), so there is no submodule to merge,
        no gitlink, no `rspade_upstream` remote, no `.gitattributes merge=ours`.
      - The framework RECORDS every write it makes to a tracked framework file
        (App\RSpade\Core\Framework\Framework_Mutations: an index + byte-exact
        shadow copies under system/storage/rsx-update/, surviving rsx:clean), so
        the offline tamper gate (rsx:framework:verify) tells a genuine local edit
        from framework churn with NO regex.
      - Every release self-describes its pristine state via a new
        system/.rspade-release.json inventory {release_id, date, files:sha256}.
      - model codegen no longer stamps a "Generated on" timestamp, so its regen
        is idempotent (this was the multi-agent merge-conflict source).

THE FIX (informational - ships automatically in system/)
    All of the above lives in system/ and arrives with the update itself. The new
    pull flow: gates (forked / IS_FRAMEWORK_DEVELOPER / production refuse) ->
    cached bare clone at system/storage/rsx-update/upstream.git + temp checkouts
    -> tamper gate -> rsync --delete of the owned zones (app/RSpade, vendor,
    node_modules, bin, docs, artisan, .rspade-release.json; storage/, .env, and
    the system/rsx symlink are never touched) -> three-way pass for the remainder
    -> rebuild (env:heal, clean, manifest:build, migrate --framework-only, bundle
    compile, post_update) -> changelog printed + prepended to
    rsx/resource/framework_update_history.dat -> NO auto-commit. Full contract:
    `php artisan rsx:man rsx_upstream`.

ACTION REQUIRED
    0. SET A LONG COMMAND TIMEOUT (10 MINUTES) for every `rsx:framework:pull`
       in this transition. The transition pulls are the SLOWEST the updater ever
       runs (uncached distribution clone + ~110k-file materialize + a full
       rebuild); a 2-minute tool timeout WILL kill the run partway and leave a
       half-finished state (recoverable, but avoidable). Run in the foreground
       with a 10-minute timeout, or detached with output to a log you poll.

    1. TRANSITION SEQUENCE (unavoidable, one time):
         a. Your NEXT ordinary pull delivers the new tooling: the old-style merge
            brings in the new TRACKED script bin/framework-pull-upstream.sh,
            which artisan's interception then runs directly on subsequent pulls.
            (There is no `.dist` template on downstream boxes - that is a
            framework-monorepo mechanism only.)
         b. The pull AFTER that detects your git-submodule topology
            (.gitmodules `path = system`) and OFFERS the one-time conversion. It
            requires confirmation (interactive Y/n; `--yes` non-interactively).
            The conversion de-inits and un-tracks the submodule, strips the
            .gitmodules entry, removes .git/modules/system, preserves a real
            system/.env, materializes system/ as ordinary files, recreates the
            system/rsx symlink, and stages `git add system`.
         c. COMMIT the conversion. It is a single LARGE commit - vendor/ and
            node_modules/ are now tracked inside your repo. This size is expected
            and was accepted by design. Conversion runs in BASELINE mode (no old
            tree), so it only adds/keeps and never deletes; the next update
            reconciles normally.

    2. CHANGE YOUR UPDATE HABIT: after a pull, the changes are LEFT IN YOUR
       WORKING TREE (nothing is auto-committed). Run your tests, then commit the
       framework update yourself. Framework updates now enter your app repo
       history; `git log -- system/` works from now on.

    3. STOP FORCE-MERGING. Do NOT run the old `merge --abort / reset --hard /
       clean -fd` recovery dance - there is no merge anymore. If the gate flags a
       file you did not mean to change, inspect it with
       `rsx:framework:pull --diff-system-changes` and discard the edit. Reserve
       `--force` for a deliberate overwrite/repair; it DESTROYS local changes
       under the framework-owned zones and takes upstream on every conflict. Never
       let an automated agent pass --force without your explicit permission.

       TRANSITION-ERA EXCEPTION (expected, one time): a box that installed an
       intermediate release during the rework rollout may see tamper-gate flags
       it did not cause - a cohort of line-ending-only diffs under vendored
       node_modules trees, and/or class-override churn (missing/.upstream/
       use-header/classmap files) with no marker attestation yet. Sanity-check
       with `--diff-system-changes`: if the findings are confined to those
       shapes, ONE authorized `rsx:framework:pull --force` heals everything
       (pristine owned zones, fresh marker ledger); `rsx:framework:verify`
       should then report clean. Anything OUTSIDE those shapes is a real local
       edit - stop and review before forcing.

    4. KEEP FRAMEWORK CUSTOMIZATIONS OUT OF app/RSpade. The owned zones are
       hard-synced (rsync --delete): any local edit under app/RSpade, vendor,
       node_modules, bin, or docs is removed on update. To customize a framework
       class, use a class override in rsx/ (rsx:man class_override); for genuine
       core ownership, fork (rsx:man framework_fork). Deliberate edits to the
       NON-owned remainder of system/ are preserved and reported by the three-way
       pass.

    5. REMOVE NO LONGER NEEDED MIRROR RULES (optional cleanup). If your GitHub
       mirror / export tooling carried omit-lists for `*.upstream` files (a
       workaround for the old merge path leaking override renames), those rules
       are now unnecessary. They are HARMLESS if left in place - the owned-zone
       sync recreates override state at build time regardless - so removing them
       is cleanup, not a requirement.

    6. WHERE FRAMEWORK HISTORY LIVES NOW. Your app repo: `git log -- system/`
       after your first post-conversion update. Upstream: the full framework
       history remains browsable at the rspade_system Gitea repo
       (git.internal.hanson.xyz/brianhansonxyz/rspade_system), and a cached clone
       sits under system/storage/rsx-update/.

RECOVERY: THE UPDATER SCRIPT ITSELF IS MISSING
    A box converted under an early rework release (or a fresh clone of such a
    repo) can be missing system/bin/framework-pull-upstream.sh entirely - the
    early releases shipped a .gitignore that hid the script from `git add
    system`, so it was never committed into the app repo. Symptom:
    `php artisan rsx:framework:pull` errors immediately with "Framework update
    script not found". Bootstrap it from the distribution, then pull normally:

        # If the cached distribution clone exists:
        git --git-dir=system/storage/rsx-update/upstream.git fetch origin master:master
        mkdir -p system/bin
        git --git-dir=system/storage/rsx-update/upstream.git \
            show master:bin/framework-pull-upstream.sh > system/bin/framework-pull-upstream.sh
        chmod +x system/bin/framework-pull-upstream.sh

        # If no cache exists yet, clone first:
        git clone --bare ssh://git@git.internal.hanson.xyz/brianhansonxyz/rspade_system.git /tmp/rspade_system.git
        # ...then the same `git show` extraction from /tmp/rspade_system.git.

    The next `rsx:framework:pull` updates the tree (current releases no longer
    ship the poisonous ignore line, and the updater force-stages its own script),
    so after you commit that update the script is tracked in your repo and every
    future clone carries it. Fresh conversions on current releases never hit this.

VERIFICATION
    1. After the conversion pull, confirm system/ is tracked files, not a gitlink:
           git ls-files system | head        # lists real files (not one gitlink)
           test -f .gitmodules && grep -c 'path = system' .gitmodules || echo ok
       (no `path = system` entry should remain).
    2. Confirm the release inventory landed:
           test -f system/.rspade-release.json && echo present
    3. Run a clean check of the framework tree:
           php artisan rsx:framework:verify        # [OK] ... verified clean
    4. Confirm status resolves your installed release + update availability:
           php artisan rsx:framework:status
    5. Confirm the update was recorded:
           head -1 rsx/resource/framework_update_history.dat
           # ## RSPADE-UPDATE <ts> from=BASELINE to=<sha>   (first time)
    6. Run your app + framework tests, then commit.
