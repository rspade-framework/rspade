CATEGORY: 2 - ACTION REQUIRED (every app)
TITLE: Every RSX page now ships a Content-Security-Policy (report-only). You
       must triage your violation log, declare your own external resources,
       and then turn enforcement on.
DATE: 2026-08-18

--------------------------------------------------------------------------------
SUMMARY
--------------------------------------------------------------------------------

Two new framework subsystems, designed as one thing:

  1. A DECLARATIVE EXTERNAL-RESOURCES REGISTRY. Every external URL a page loads
     (a CDN library, a vendor widget) is declared in a `*.externals.php` file
     beside the feature that needs it, and loaded by identifier:

         await Rsx.load_external('chartjs');

  2. A COMPOSED CONTENT-SECURITY-POLICY, emitted on every dispatched HTML
     response, per realm (staff / portal). Its external-origin whitelist is
     DERIVED from those declarations - there is no policy string to maintain.

     Framework inline scripts carry a nonce; `'unsafe-inline'` never appears in
     script-src.

It ships as Content-Security-Policy-REPORT-ONLY: the browser evaluates the
policy, POSTs every violation to the new /_csp-report collector, and loads the
resource anyway. NOTHING IS BLOCKED TODAY. Your application behaves exactly as
before this pull.

That is the whole reason this document exists. Report-only is a SILENT state:
you get the reports and none of the protection, nothing breaks, and nothing
tells you the policy is not actually protecting anything. Turning it on is
YOUR job and cannot be done for you - only you can exercise your own screens.

Full contract:  php artisan rsx:man csp
                php artisan rsx:man external_resources

--------------------------------------------------------------------------------
ACTION REQUIRED
--------------------------------------------------------------------------------

STEP 1 - FIND YOUR OWN EXTERNAL RESOURCES AND DECLARE THEM

Anything your app injects at an external host today - a hand-written <script>
tag in a Blade layout, a vendor copy-paste snippet, an appendChild in a
component - will be REPORTED now and BLOCKED once you enforce. Find them:

    # external <script>/<link> in your markup
    grep -rn 'src="https\?://' rsx/ --include=*.blade.php --include=*.jqhtml
    grep -rn 'href="https\?://' rsx/ --include=*.blade.php --include=*.jqhtml | grep -i 'stylesheet\|\.css'

    # runtime injection from JavaScript
    grep -rn "createElement('script')\|createElement(\"script\")" rsx/
    grep -rn 'appendChild' rsx/ | grep -i 'script\|link'
    grep -rn 'document.write' rsx/

    # inline <script> blocks in your own pages (these are reported too)
    grep -rn '<script' rsx/ --include=*.blade.php --include=*.jqhtml

For each external URL, write a declaration beside the feature that needs it.
The file may be named anything ending in `.externals.php`, and MUST NOT live
under a `resource/` or `public/` directory - those are manifest-invisible, and
a declaration there is simply never discovered.

    File: rsx/app/frontend/reports/charts.externals.php
    ---------------------------------------------------------------------------
    <?php

    return [
        'chartjs' => [
            'js'    => ['https://cdn.jsdelivr.net/npm/chart.js@4.4.1/dist/chart.umd.min.js'],
            'realm' => 'staff',          // 'staff' | 'portal' | 'both' (default)
            // 'mirror' => false,        // for a vendor endpoint serving DYNAMIC bytes
            // 'integrity' => ['https://...' => 'sha384-...'],
            // 'readiness' => ['callback_param' => 'onload'],
            // 'csp' => ['frame-src' => ['https://vendor.example']],
        ],
    ];

Then delete the hand-injection and load by identifier where the feature needs
it - not at page load:

    async on_load() {
        await Rsx.load_external('chartjs');
        this.state.chart = new Chart(this.$sid('canvas')[0], { ... });
    }

An INLINE <script> block in your own markup is not a declaration case: move
the code into a bundled .js file (with a page guard for a Blade page). Do NOT
reach for the nonce - it exists for framework-emitted bootstrap markup only.

A library your app needs in the HEAD of every page stays a bundle `cdn_assets`
entry; that path is unchanged and its origins are whitelisted automatically.

STEP 2 - ADD THE CONFIG BLOCK TO YOUR APP CONFIG

The framework defaults are already correct; this block is where you will make
the rollout decisions in steps 4 and 5. Add it to your fork:

    File: rsx/resource/config/rsx.php
    ---------------------------------------------------------------------------
    // 'csp' => [
    //     // Stop observing, start blocking (do this once the violation log is clean)
    //     'report_only' => false,
    //
    //     // TRANSITIVE origins only: hosts a DECLARED script goes on to fetch
    //     // by itself, which no declaration can enumerate.
    //     'additional_sources' => [
    //         'script-src'  => ['https://...'],
    //         'connect-src' => ['https://...'],
    //         'img-src'     => ['https://...'],
    //     ],
    // ],

STEP 3 - EXERCISE THE APPLICATION AND READ THE LOG

Deploy (or run locally) and walk EVERY screen: both realms, every third-party
widget, file upload and preview, print views, error screens, the login and
password-reset flows. A violation only appears if a real page load produces it.

    tail -n 100 storage/logs/csp_violations.log

    # readable triage
    cat storage/logs/csp_violations.log | jq -r \
      '.report | "\(.["effective-directive"]) <- \(.["blocked-uri"]) on \(.["document-uri"])"' \
      | sort | uniq -c | sort -rn

In development the browser console also prints an [RSX CSP] warning naming the
directive, the blocked URI and the remedy.

STEP 4 - TRIAGE EVERY LINE

Each violation has exactly one correct fix:

    A resource your PAGE loads itself
        -> declare it (step 1) and load it by identifier.

    An origin a DECLARED script fetches on its OWN (analytics, tag manager,
    a vendor loader pulling further vendor code)
        -> add the origin to csp.additional_sources. This is the ONLY thing
           that key is for. It is widen-only; object-src is refused outright.

    An inline <script> in your own markup
        -> move the code into a bundled .js file.

    A violation naming eval / the Function constructor from FRAMEWORK code
        -> STOP. Do not add 'unsafe-eval' yourself and do not enforce. Report
           it upstream: whether the framework needs that source is a framework
           decision, and adding it gives back much of what CSP is for.

STEP 5 - ENFORCE

When a full pass leaves the log clean, set in rsx/resource/config/rsx.php:

        'csp' => ['report_only' => false],

The header becomes Content-Security-Policy and the browser starts blocking.
Walk the application once more after the flip.

This step is also ENTRY 6 of `php artisan rsx:man prelaunch_checklist`.

--------------------------------------------------------------------------------
ALSO IN THIS RELEASE - @rsxData IS DELETED
--------------------------------------------------------------------------------

The `@rsxData([...])` Blade directive is gone (it emitted an un-nonce'd inline
script and had zero usages anywhere). It was never documented as a supported
API, but check:

    grep -rn 'rsxData' rsx/

Any hit is now a fatal "unknown directive" at render. Replace it by passing the
data through your bundle's page data (`@rsx_page_data` / the bundle's
load_rsxapp_data) and reading it from window.rsxapp.page_data.

--------------------------------------------------------------------------------
NOTES AND EDGE CASES
--------------------------------------------------------------------------------

SEALED BUILDS MIRROR YOUR EXTERNALS. rsx:prod:enable / rsx:prod:refresh gained
an explicit step, "[2/5] Mirroring external assets", that downloads every
`mirror:true` declared URL into rsx/resource/.cdn-cache/ (committed to git). A
sealed build then serves them from /_vendor/ and NEVER downloads at request
time - a missing mirror file now THROWS instead of silently curling the asset.
If you declare a resource whose bytes are dynamic (a vendor endpoint serving
per-client JavaScript), declare `'mirror' => false` or the sealed build will
serve a stale, wrong copy.

FULL PAGE CACHE. An #[FPC] page's cached HTML is replayed by the FPC proxy
without the CSP header, so cached public pages carry no policy today. If a
public page's protection matters, do not mark it #[FPC].

PORTAL ON A SEPARATE DOMAIN. /_csp-report is served by the staff dispatcher.
With the default path-prefix portal this is fine. If you serve your portal from
its own DOMAIN, route that path there too or your portal's reports are lost.

TURNSTILE. If you use it, nothing changes for you - the framework moved its
api.js onto the registry and declares its own CSP needs. Do not add
challenges.cloudflare.com to additional_sources.

--------------------------------------------------------------------------------
VERIFICATION
--------------------------------------------------------------------------------

1. Headers are present on a dispatched page:

       curl -sI https://your.host/login | grep -i content-security-policy
           -> Content-Security-Policy-Report-Only: ... (or Content-Security-Policy
              once you have enforced)

2. grep -rn 'createElement(.script.)\|document.write\|rsxData' rsx/
       -> no hits left that inject an external or inline script.

3. Every external URL your app uses appears in a `*.externals.php` file:

       grep -rn 'https://' rsx/ --include=*.externals.php

4. After a full walk of the application, storage/logs/csp_violations.log gains
   NO new lines.

5. With 'report_only' => false, walk the application again: no blocked
   resources in the browser console, and the log stays clean.

6. php artisan rsx:prod:refresh on a sealed host completes its
   "[2/5] Mirroring external assets" step and pages render with /_vendor/ URLs.
