RECOVERING A BOX A BACKWARDS MERGE MOVED OFF ITS FRAMEWORK RELEASE
Date: 2026-08-18
Category: 2 (framework-core behavior change) - MANUAL ACTION REQUIRED ONLY ON A BOX
          THAT HAS ALREADY BEEN REGRESSED

SUMMARY
    Two framework changes ship together in this release:

      1. `rsx:git pull` / `rsx:git merge` now decide the framework RELEASE before
         merging (Phase 0), and restate the winning side's system/ tree wholesale.
         A peer that is a release behind can no longer push its system/ tree onto
         a current box, whether by conflict or by silent deletion.
      2. `rsx:framework:pull` reads system/.rspade-release.json as the SOLE
         authority for what release is installed. rsx/resource/framework_update_history.dat
         is now a log; when it disagrees with the marker the run says so and trusts
         the marker.

    Both are automatic. NO ACTION IS REQUIRED on a healthy box.

    ACTION IS REQUIRED IF this already happened to you - i.e. a `rsx:git pull` moved
    system/ BACKWARDS to an older release (the pull printed "moved system/ BACKWARDS"),
    and/or a subsequent `php artisan rsx:framework:pull` printed
    "Framework baseline repair <old_release_id>" and untracked thousands of paths.
    Symptoms: every rebuild fails (e.g. "Manifest scan path does not exist: 'rsx'"),
    `git status` shows a large number of untracked files under system/, and
    `rsx:framework:verify` reports missing framework files.

    Recovery is `php artisan rsx:framework:pull --resync` - but that command lives in
    the NEW updater, and a regressed box is running the OLD one. Read the bootstrap
    below before typing anything.

BEFORE ANYTHING ELSE: DO NOT RUN A TREE-REWRITING rsx:git OPERATION
    A regressed box typically holds NEW-release framework files on disk that the bad
    repair commit left UNTRACKED. `rsx:git pull` (and merge / rebase / checkout /
    reset --hard / clean - the whole maintenance class) resets system/ to HEAD and runs
    `git clean -fdq -- system` first, which DELETES exactly those files. They are the
    only copy you have.

    So until the resync below has run and committed:

        DO NOT run  php artisan rsx:git pull
        DO NOT run  php artisan rsx:clean --force
        DO NOT run  git clean under system/

    Ordinary reads (status, log, diff, show) are safe. Committing app work is safe.

STEP 1 - CONFIRM THE REGRESSION AND FIND THE PRE-MERGE COMMIT
    The release marker is the record of what your tree held and when:

        git log --format='%h %cd %s' -- system/.rspade-release.json

    Read the marker at each of the last few commits until you find the newest release
    your box actually had:

        git show <sha>:system/.rspade-release.json | head -3

    Compare it with what is on disk now:

        head -3 system/.rspade-release.json

    If the on-disk release_id/date is OLDER than the one at some earlier commit, this
    document applies. Call that earlier commit <PRE> below.

STEP 2 - BOOTSTRAP: PUT THE NEWER UPDATER BACK
    THE PROBLEM, STATED PLAINLY. The recovery command is `rsx:framework:pull --resync`,
    and the code that implements it lives in system/bin/framework-pull-upstream.sh -
    which is part of the tree that got regressed. Your box is running the OLD updater,
    and on top of that its history.dat may still claim the box is up to date, so a plain
    `php artisan rsx:framework:pull` can short-circuit before it ever syncs the fixed
    script. Nothing self-heals here: the release cannot deliver the fix through an
    updater that refuses to run.

    So restore the updater from YOUR OWN pre-merge history first. Use PLAIN GIT, not
    rsx:git - the proxy's maintenance cycle would clean untracked system/ files (see
    above):

        git checkout <PRE> -- system/bin system/artisan
        chmod +x system/bin/framework-pull-upstream.sh

    That is the minimal correct set. system/bin/ and system/artisan are framework-OWNED
    zones - the pull hard-syncs them from the release on every run - so restoring them
    destroys nothing and needs no flag. system/artisan is included because it is the
    pre-boot interceptor that forwards the command to the script.

    If <PRE> does not carry a usable updater either (a box provisioned from an older
    release), extract the tracked script straight from the distribution cache instead:

        git --git-dir=/tmp/rspade_upstream.git show \
            master:bin/framework-pull-upstream.sh > system/bin/framework-pull-upstream.sh
        chmod +x system/bin/framework-pull-upstream.sh

    (If /tmp/rspade_upstream.git does not exist, clone the distribution bare first -
    the same URL your updater uses.)

STEP 3 - RESYNC TO THE DISTRIBUTION TIP

        php artisan rsx:framework:pull --resync

    What it does: restores every framework-owned zone to the distribution tip (absent
    files restored, unmodified files synced), three-way reconciles the rest, and
    re-commits system/ as that release. It never short-circuits on a marker.

    It is NOT --force. Locally modified files still go through the tamper gate and the
    three-way pass, so accepted committed drift in your own tree survives - that is the
    entire reason to use --resync rather than `--force`. If the tamper gate stops you,
    it is naming real unauthorized edits under an owned zone; deal with those on their
    own merits (`--diff-system-changes` shows them) and do not reach for --force to get
    past this step.

STEP 4 - VERIFY, THEN RESUME NORMAL WORK

        php artisan rsx:framework:verify
        php artisan rsx:manifest:build
        git status --short -- system        # expect: nothing but gitignored build state

    Only now is `php artisan rsx:git pull` safe again.

STEP 5 - FIX THE BOX THAT SENT IT
    A backwards merge means another environment is sitting on an old framework release
    and pushing it. From this release on, `rsx:git pull` names that box for you:

        origin/master carries release <id> (<date>), N days behind;
        last written by <committer> - that box needs a pull or it will keep re-sending this.

    Run `php artisan rsx:framework:pull` there. Until you do, every pull on the current
    box will discard its tree again (correctly, and silently apart from that one line).

WHAT CHANGED, FOR THE RECORD
    * rsx:git pull/merge: Phase 0 reads system/.rspade-release.json on both refs before
      merging. Newer date wins wholesale; the same release_id restates silently; an
      EQUAL date with a DIFFERENT release_id REFUSES the operation and asks; a missing
      or unparseable marker falls back to a plain git merge with a loud warning.
    * The per-file "resolve system/ conflicts to the incoming side" policy, its
      rebase --ours/--theirs inversion, and its keep-local patch are GONE. They answered
      a whole-tree question one file at a time and could not see the shape that actually
      loses code: a non-conflicting incoming deletion.
    * The "moved system/ BACKWARDS" error still exists, but it is now a post-condition -
      unreachable by construction. If you ever see it again, the reconciliation itself
      is wrong; report it.
    * rsx:framework:pull: the marker is the sole authority for the installed release;
      framework_update_history.dat is log-only; a baseline repair refuses to run against
      a marker older than the distribution tip and syncs forward instead.
    * New flag: --resync (see rsx:man rsx_upstream, FLAGS).

    Full treatment: `php artisan rsx:man rsx_git`, `rsx:man rsx_upstream`,
    `rsx:man framework_pull_mechanics`.
