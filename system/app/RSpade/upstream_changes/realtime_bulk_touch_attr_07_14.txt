REALTIME PHASE 2 - #[Realtime_Touch] ATTRIBUTE + BULK EMISSION COVERAGE + BULK FRAMES (CORE ADDITIONS)
Date: 2026-07-14

SUMMARY
    The realtime model-emission system (shipped 2026-07-13) gained four
    framework-core additions: a #[Realtime_Touch] relationship attribute (the new
    preferred way to declare a parent touch), automatic realtime emission on bulk
    model-builder writes, coalesced bulk WebSocket frames, and a #[Emitter] model
    constraint enabling derived values to compose onto the shared
    Model_Changed_Topic. A new rsx:check rule (REALTIME-BULK-01) surfaces
    uncovered bulk writes. All of it is opt-in/backward-additive - an app that
    adopts nothing keeps working - EXCEPT one operational step (redeploy the Node
    relay) and one reserved-name to be aware of. Your existing realtime_touch()
    overrides continue to work unchanged.

THE CHANGE
    Additions to /system/ core (all arrive automatically via the submodule):

    1. #[Realtime_Touch] attribute - the new way to declare a touch.
       A bare marker attribute (no arguments) placed on a child model's belongsTo
       relationship method. Any write to that child - a model save()/delete() OR a
       covered bulk builder write (item 2) - queues a change emission for the
       related PARENT, resolved once per class by reflecting the annotated
       relationship (parent class + FK column; no FK duplicated in the attribute).

           // Contact_Model
           #[Relationship]
           #[Realtime_Touch]
           public function client()
           {
               return $this->belongsTo(Client_Model::class, 'client_id');
           }

       Key properties:
       - Fires INDEPENDENTLY of the child's own $realtime flag (a touch-only child
         can leave $realtime off and still refresh its parent). This closes the
         Phase 1.2 "touch-only is dead code on a non-$realtime model" trap.
       - belongsTo-ONLY. On a hasMany / morphTo / hasOne / non-belongsTo method it
         FAILS LOUD at resolution. For a polymorphic or conditional parent, the
         realtime_touch(): array method remains the escape hatch (see item 6).
       - "Realtime_Touch" is now a RESERVED attribute name on relationship methods
         (like #[Relationship], #[Emitter]). It is reflection metadata only - never
         define the attribute class; the linter strips any `use` for it.

    2. Bulk model-builder writes now auto-emit.
       Model::where(...)->update([...]) and Model::where(...)->delete() on a model
       with a realtime SURFACE ($realtime = true, OR a #[Realtime_Touch]-attributed
       relation, OR an overridden realtime_touch()) now emit change notifications
       for the affected rows - previously they bypassed emission entirely.

       PERFORMANCE NOTE (the thing to be aware of): to know which rows a bulk write
       affects, the model builder runs a bounded, light-column pre-SELECT (id, the
       attributed FK columns, site_id) immediately before the write, on
       realtime-surface models only. This is an extra query on those bulk writes.
       Two escape valves:
       - ->without_realtime() chained onto the statement skips the pre-select +
         emission for that ONE statement (huge maintenance sweeps).
       - A 5000-row CAP: a statement affecting more than 5000 rows skips emission
         ENTIRELY (never a partial notification set) and logs a console_debug note.
       SoftDeletes ->delete() (an UPDATE of deleted_at) is covered on the same
       path. DB::table()/raw SQL/->getQuery() drops are NOT model-builder writes and
       still emit nothing - realtime_emit() remains the manual tool there.

    3. Coalesced bulk WebSocket frames.
       When one request produces several changes to the SAME model on the SAME
       site, they now transmit as ONE Model_Changed_Topic frame carrying
       {model, ids:[...]} (chunked ~100 ids/frame) instead of N singleton
       {model, id} frames. A single-record group keeps the {model, id} shape. The
       Node relay and the JS client matcher were both updated so an id-filtered
       watcher ({id: 5}) matches a frame whose `ids` array CONTAINS its id;
       collection watchers ({model} only) match either shape.

    4. REALTIME-BULK-01 (rsx:check, medium/advisory). Flags a bulk
       ->update()/->delete() reached through a Model::where()/query() chain on a
       realtime-surface model, and a DB::table('<table>')->update()/->delete()
       whose table maps to such a model. Advisory because model-builder writes are
       now auto-covered (item 2); its real prey is the DB::table/raw path that
       genuinely emits nothing. Three suppressions clear it: (a) the same chain
       calls ->without_realtime(), (b) the enclosing method body calls
       realtime_emit(), (c) a // @REALTIME-BULK-01-EXCEPTION - <rationale> comment.

    5. #[Emitter] optional model constraint.
       #[Emitter('Topic', 'Model_Name')] - an OPTIONAL second positional argument -
       scopes the emitter to registry entries whose filter.model matches. Absent,
       an emitter behaves exactly as before (custom topics unchanged). Present, it
       is what makes composing a derived value onto the shared Model_Changed_Topic
       safe: without it, such an emitter would make EVERY model write dispatch the
       recompute task and fan out to every watched record (the no-churn property
       lost). Lets a page keep the single this.subscribe(Model, id, ...) idiom for
       a computed value.

    6. Template models moved to the attribute (informational).
       In the /rsx/ starter template, Contact_Model / Project_Model and the portal
       request thread/message models were refactored FROM a realtime_touch()
       override TO #[Realtime_Touch] on their belongsTo parent method. Task_Model
       KEPT its realtime_touch() (its taskable parent is polymorphic - the escape
       hatch case). This is the template demonstrating the preferred pattern; it
       does not obligate you to migrate.

THE FIX
    Informational only - all of the above lives in /system/ and reaches you via
    the submodule merge on the next `php artisan rsx:framework:pull`. There is
    nothing here to copy into your own code.

ACTION REQUIRED
    For MOST apps: redeploy the relay (item 1 below) and glance at item 2. The
    rest is optional adoption.

    1. Redeploy / restart the Node relay (REQUIRED if you run realtime).
       The bulk-frame matcher change ships in realtime-server.js. An OLD relay does
       NOT understand {model, ids:[...]} frames, so an id-filtered subscriber would
       MISS bulk-write notifications until you restart it. After pulling, restart
       the relay (e.g. `supervisorctl restart realtime`). If you do not run a relay
       (realtime disabled), skip.

    2. Reserved-name check. "realtime_touch" was already reserved (Phase 1);
       "Realtime_Touch" is now ALSO reserved as a relationship-method attribute. If
       any of your relationship methods carry an unrelated attribute named
       Realtime_Touch, rename it. (New/typical apps will not hit this.)

    3. Your existing realtime_touch() overrides: NO ACTION - still fully supported.
       The method surface is unchanged. Bulk writes on a model that uses the method
       are covered by HYDRATING the affected rows (rather than a light pre-select),
       because the method needs a real instance. You may migrate a plain-belongsTo
       override to #[Realtime_Touch] for the lighter path, but you are not required
       to, and a polymorphic/conditional parent MUST stay on the method.

    4. Run rsx:check after pulling. REALTIME-BULK-01 may flag existing bulk writes
       in your code. For a model-builder write it is advisory (already auto-covered
       - keep it, or ->without_realtime() a deliberate huge sweep). For a
       DB::table()/raw write against a realtime-surface model it is real: add a
       $record->realtime_emit() after the write, rewrite it as a model-builder
       write, or suppress with a rationale comment.

    5. Adopting the new surface (optional):
       - Replace a plain-belongsTo realtime_touch() with #[Realtime_Touch] on the
         relationship method.
       - Rely on bulk auto-emission instead of a manual realtime_emit() after a
         Model::where()->update().
       - Compose a derived value onto Model_Changed_Topic with
         #[Emitter('Model_Changed_Topic', 'Your_Model')].
       Full guide: `php artisan rsx:man realtime` (MODEL CHANGE EMISSION / BULK
       WRITES, DERIVED VALUES, EMITTERS).

    When you have redeployed the relay (item 1) and checked items 2 + 4, mark this
    change fulfilled:

        php artisan rsx:framework:upstream_changes:mark realtime_bulk_touch_attr_07_14 --fulfilled

VERIFICATION
    Framework-side coverage: the realtime suite
    (`php artisan rsx:test --framework --filter=Realtime`) locks down the attribute
    touch (child save queues the parent emission; fires without the child's own
    $realtime; dedupes with the parent's own save; onward cascade still walks),
    bulk update/delete emission (own + parent for affected rows only; soft-delete
    variant; ->without_realtime() suppresses; cap behavior; rollback discard), the
    {model, ids} frame grouping/chunking, the rule, and the emitter model
    constraint.

    For your own code:
    - Confirm no relationship method carries an unrelated Realtime_Touch attribute.
    - With the relay restarted: open a page subscribed via this.subscribe(Model,
      id, ...), run a bulk Model::where(<fk>, id)->update([...]) that touches that
      record (or its children) from another tab/CLI, and confirm the page refreshes
      exactly once. Confirm ->without_realtime() on the same statement does NOT
      refresh it.
