LIBPHONENUMBER-BACKED PHONE FORMATTING (PHP + JS PARITY)
Date: 2026-07-11

SUMMARY
    The template app's phone formatting is now backed by Google's
    libphonenumber on both platforms: Formatters::phone() (PHP) and a new
    Formatters.phone() (JS) produce byte-identical output, including real
    international formatting for '+'-prefixed numbers (previously passed
    through raw with no formatting at all) and an optional region parameter
    for non-US national formats. US formatting output is unchanged
    ((XXX) XXX-XXXX, progressive partials included), so existing stored data
    displays exactly as before. Phone_Text_Input now formats a completed
    international number on blur instead of leaving it untouched.

    The underlying libraries arrive automatically via the framework layer -
    giggsey/libphonenumber-for-php (composer) and google-libphonenumber (npm)
    both ship in system/ with your next `php artisan rsx:framework:pull`.
    This document covers only the /rsx/ template changes you replicate by
    hand. Both libraries are ports of the same Google library sharing the
    same metadata, which is what makes identical PHP/JS output possible.

BEHAVIOR CONTRACT (both platforms, identical)
    phone(input, region = 'US'):
    1. null/undefined/'' -> '' (strict check: the string '0' proceeds to
       formatting and yields "(0" on both platforms - this closes a previous
       PHP/JS divergence where PHP's empty() short-circuited '0').
    2. Input starting with '+' (trimmed): parsed with libphonenumber (region
       irrelevant); if parseable AND isPossibleNumber -> INTERNATIONAL
       format; otherwise returned unchanged. Uses isPossibleNumber(), NOT
       isValidNumber(), so test/placeholder numbers survive.
    3. No '+' and region 'US' (default): the digit-stripping + progressive
       US formatting logic, unchanged output (11-with-leading-1 strips the
       1; >10 digits truncate to first 10; partials format progressively
       including the trailing-space quirk for 3-5 digit input).
       Deliberately NOT routed through libphonenumber so invalid-plan
       placeholder numbers (555 area codes etc.) and partial input survive.
    4. No '+', explicit non-US region: parse(input, region); if possible ->
       that region's NATIONAL format; else unchanged.

    Canonical outputs (locked by tests):
        phone('5551234567')            -> '(555) 123-4567'
        phone('15551234567')           -> '(555) 123-4567'
        phone('+442071234567')         -> '+44 20 7123 4567'
        phone('+9999999')              -> '+9999999'   (not possible)
        phone('123')                   -> '(123) '     (progressive partial)
        phone('0')                     -> '(0'
        phone('2071234567', 'GB')      -> '020 7123 4567'

    File: /rsx/lib/formatters.php
    -------------------------------------------------------------------------
    Add use statements at top of file:

        use libphonenumber\PhoneNumberUtil;
        use libphonenumber\PhoneNumberFormat;
        use libphonenumber\NumberParseException;

    Replace the phone() method body (keep _format_us_phone() unchanged):

        public static function phone(?string $input, string $region = 'US'): string
        {
            // Strict null/'' check (not empty()) so the string '0' proceeds to
            // formatting, matching Phone_Text_Input.
            if ($input === null || $input === '') {
                return '';
            }

            // International mode - input carries an explicit country code ('+').
            if (str_starts_with(trim($input), '+')) {
                try {
                    $proto = PhoneNumberUtil::getInstance()->parse($input, null);
                    if (PhoneNumberUtil::getInstance()->isPossibleNumber($proto)) {
                        return PhoneNumberUtil::getInstance()->format($proto, PhoneNumberFormat::INTERNATIONAL);
                    }
                } catch (NumberParseException $e) {
                    // Expected for arbitrary display input - fall through.
                }
                return $input;
            }

            // Non-US region - defer to libphonenumber's NATIONAL format.
            if ($region !== 'US') {
                try {
                    $proto = PhoneNumberUtil::getInstance()->parse($input, $region);
                    if (PhoneNumberUtil::getInstance()->isPossibleNumber($proto)) {
                        return PhoneNumberUtil::getInstance()->format($proto, PhoneNumberFormat::NATIONAL);
                    }
                } catch (NumberParseException $e) {
                    // Expected for arbitrary display input - fall through.
                }
                return $input;
            }

            // US mode - existing digit logic, unchanged from before.
            $digits = preg_replace('/[^0-9]/', '', $input);
            $digits_to_format = '';
            if (strlen($digits) === 11 && $digits[0] === '1' && preg_match('/[2-9]/', $digits[1])) {
                $digits_to_format = substr($digits, 1);
            } elseif (strlen($digits) > 10) {
                $digits_to_format = substr($digits, 0, 10);
            } else {
                $digits_to_format = $digits;
            }
            return self::_format_us_phone($digits_to_format);
        }
