REALTIME MODEL CHANGE EMISSION + EMITTER ENGINE (CORE ADDITIONS)
Date: 2026-07-13

SUMMARY
    The framework-core realtime system gained a large opt-in surface: models
    can auto-publish "record N changed" notifications, a touch cascade lets a
    child refresh a parent's result set, and an #[Emitter] engine publishes
    computed values on change. A new core topic (Model_Changed_Topic), new Redis
    registry keys, new .env keys, and a bundler change ship with it. All of it
    is OPT-IN and default-off: an app that adopts nothing keeps working exactly
    as before. This document exists so you know the new contract, the one
    naming collision to avoid, and the ONE operational step (redeploy the Node
    relay) needed to get the emitter/registry feature.

THE CHANGE
    Additions to /system/ core (all arrive automatically via the submodule):

    1. Rsx_Model_Abstract gained three members:
         public static $realtime = false;          // opt into change emission
         public static $realtime_silent = false;   // suppress the emitter kick
         public function realtime_touch(): array;   // parent instances to notify
       When $realtime is true, a successful save()/delete() (the model write
       choke point) queues a notification-only Model_Changed_Topic {model, id}
       message, flushed on transaction COMMIT (rollback discards; deduped per
       model|id|site_id). Query-builder writes (DB::table()->update(),
       Model::where()->update(), raw SQL) bypass the model layer and emit
       nothing, by design. realtime_touch() returns parent model INSTANCES whose
       result sets depend on this record; the cascade notifies them too
       (cycle-guarded, depth-capped 25) WITHOUT writing any parent row.

    2. Model_Changed_Topic (App\RSpade\Core\Realtime\Model_Changed_Topic) ships
       in core: the single topic all opt-in model changes publish to. Its
       can_subscribe() gate is "is a signed-in user" (staff OR portal) - the
       owner's stance, because messages are notification-only {model, id} hints
       and the subscriber's own fetch()/portal_fetch() still enforces read
       access on refetch.

    3. #[Emitter('Topic')] engine: a public static (int $site_id, array $filter):
       mixed carrying #[Emitter] is discovered by manifest attribute scan; the
       Realtime_Emitter_Service::run_emitters task (#[Task] #[Debounce(2)])
       recomputes each live-subscribed emitter, hash-diffs it, and publishes its
       topic only on change. There is NO timer - a non-silent model write kicks
       the task, gated so it runs only when a live subscriber watches a topic
       that actually has an emitter.

    4. Node subscriber registry: realtime-server.js now maintains a Redis SET
       rsx_rt:subs (canonical {site_id, topic, filter} members) rewritten on
       every subscribe/unsubscribe/close, and emitter value-hashes live under
       rsx_rt:em:*. Both are under the existing rsx_rt: namespace.

    5. New .env keys (see ACTION REQUIRED).

    6. BundleCompiler now ALWAYS includes the Realtime_Controller JS stub in
       every app bundle. The always-bundled core Rsx_Realtime.js depends on that
       controller's Ajax endpoints; without the stub, the first subscribe threw
       "Realtime_Controller is not defined". This was latent (realtime had zero
       live consumers before). No app action - it just works now.

    7. JS: this.subscribe() gained model overloads
       (subscribe(Model_Class, id, cb) and subscribe(record, cb) ->
       Model_Changed_Topic), is now IDEMPOTENT per (topic, filter) per component
       instance, and FAILS LOUD when the model has not opted in. Rsx_Js_Model
       gained watch_changes(id, cb) for non-component code.

THE FIX
    Informational only - all of the above lives in /system/ and reaches you via
    the submodule merge on the next `php artisan rsx:framework:pull`. There is
    nothing here to copy into your own code.

ACTION REQUIRED
    For MOST apps: NONE. The whole surface is opt-in and default-off. You only
    act if one of the following applies.

    1. Redeploy / restart the Node relay (operational, do this once).
       The registry + emitter features need the updated realtime-server.js. If
       you run the relay, restart it after pulling so rsx_rt:subs starts being
       maintained. If you do NOT run a relay (realtime disabled), skip - nothing
       changes for you.

    2. Add the .env keys IF you are enabling realtime:

           REALTIME_ENABLED=true
           REALTIME_WS_PORT=6200
           REALTIME_PUBLIC_URL=wss://yourdomain/ws   # or ws://localhost:6200 in dev

       Proxy wss:// through your web server (nginx `location /ws { ... }` - see
       `php artisan rsx:man realtime`, DEPLOYMENT CONSIDERATIONS).

    3. Naming collision check (the one thing that could break silently).
       Rsx_Model_Abstract now defines the statics $realtime and $realtime_silent
       and the method realtime_touch(). If any of YOUR models already declares a
       member named `realtime`, `realtime_silent`, or `realtime_touch` for an
       unrelated purpose, it now collides with / overrides core behavior. Grep:

           grep -rn "realtime" rsx/models --include="*.php"

       Rename any app member that shadows these three. (New apps forked from the
       current template will not hit this.)

    4. Adopting the feature (optional, when you want a page to go live):
         - Set `public static $realtime = true;` on the model.
         - Override realtime_touch() to return parent INSTANCES (never null) when
           a child change must refresh a parent result set.
         - In the component: `this.subscribe(Model_Class, id, () => this.reload());`
         - For a computed value, write an #[Emitter] method and a topic class.
       Full guide: `php artisan rsx:man realtime` (MODEL CHANGE EMISSION,
       EMITTERS).

    5. Stricter per-record gating (optional). Model_Changed_Topic's gate is
       "any signed-in user." If a specific model's mere existence/change is
       itself sensitive (rare - the payload is only {model, id}), define your OWN
       topic with a tighter can_subscribe() and publish to it explicitly rather
       than relying on the shared core topic.

    When you have checked item 3 (and adopted or deliberately skipped the rest),
    mark this change fulfilled:

        php artisan rsx:framework:upstream_changes:mark realtime_model_emission_07_13 --fulfilled

VERIFICATION
    Framework-side coverage: the realtime test suite
    (`php artisan rsx:test --framework --filter=Realtime`) locks down buffer
    dedupe, afterCommit flush (immediate / deferred / rollback-discard), the
    touch cascade + cycle guard + depth cap, site_id resolution, emitter
    discovery, the smart dispatch gate, and the hash-diff seed/change/unchanged
    engine.

    For your own code:
    - Confirm the grep in ACTION REQUIRED item 3 surfaces no app member
      shadowing $realtime / $realtime_silent / realtime_touch.
    - If you adopted the feature: open a page subscribed via
      this.subscribe(Model, id, ...), save the record from another tab/CLI, and
      confirm the page reloads exactly ONCE per save (linear, not exponential -
      the idempotence contract). Confirm a rolled-back save publishes nothing.
