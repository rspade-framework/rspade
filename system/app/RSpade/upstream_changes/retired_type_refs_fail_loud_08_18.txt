CATEGORY: 2 - ACTION REQUIRED (only if any _type_refs row names a class you
          have deleted or renamed)
TITLE: A type ref whose model class no longer exists now FAILS LOUD on every
       read path - records referencing one will throw where they previously
       returned a phantom class name or a cryptic Laravel fatal
DATE: 2026-08-18

--------------------------------------------------------------------------------
SUMMARY
--------------------------------------------------------------------------------

When a model class is deleted or renamed, its _type_refs row survives. Before
this change the registry had no concept of a registered-but-retired class, and
the debris failed silently, three different ways:

    - register_morph_map() dropped the unresolvable alias without a word, so
      morphTo() over an affected row died inside Laravel with
      "Class name must be a valid object or a string" - no table, no column,
      no row id, no class name.
    - The cast returned the phantom class name ("Event_Model") to app code,
      deferring the failure to an arbitrary later frame, or nowhere.
    - class_to_id() kept issuing the retired id on the cache-hit path, so NEW
      dangling references could still be written.

All three now fail loud, at the point of use, naming the type ref id and the
retired class. Boot never throws: a retired ref nothing references costs you
one log warning and one rsx:health WARN row, not an outage.

--------------------------------------------------------------------------------
THE CHANGE (informational - arrives automatically with the pull)
--------------------------------------------------------------------------------

Type_Ref_Registry:

    - register_morph_map() registers every unresolvable (id, class_name) pair
      as a POISON alias whose instantiation throws the full story, and logs
      one warning naming every retired pair.
    - id_to_class() throws when the registered class no longer resolves
      (so the cast throws instead of returning a phantom string).
    - class_to_id() validates on the cache-hit path too - a retired class can
      no longer accrue new references.
    - NEW: Type_Ref_Registry::find_id_by_class_name(string): ?int - no
      auto-create, no manifest validation, null for unknown. This is the
      supported lookup for a cleanup migration (class_to_id() throws for
      precisely the retired classes a cleanup is about; do not query
      _type_refs directly).

Audit surface:

    - rsx:health gains a "Type References" check: WARN (never FAIL) per
      unresolvable registry row, with a per-table/column referencing-row
      count - the difference between "harmless leftover" and "your app is
      throwing right now".
    - NEW command: php artisan rsx:type_refs:prune [--dry-run] - drops
      registry rows with no live class AND no referencing data; refuses
      loudly (with the table/column/count breakdown) while data still points
      at one.

Contract documentation: rsx:man polymorphic, BOUNDARIES section (which
previously described a fail-loud that did not exist) + a RETIRING A MODEL
checklist.

--------------------------------------------------------------------------------
ACTION REQUIRED
--------------------------------------------------------------------------------

1. After pulling, run:

       php artisan rsx:health

   Look for WARN rows under "Type References". No WARN rows = you are done.

2. For each reported retired type ref WITH referencing rows: those records
   now THROW on any read that touches the polymorphic column (relation,
   cast, or a batched ORM fetch that happens to include one - note the blast
   radius: one poisoned record fails the whole batch, so an unrelated page
   can show a generic load error). Repoint or delete the referencing rows in
   a migration. Resolve the id by class name, never hardcode it (ids are
   per-environment):

       $id = Type_Ref_Registry::find_id_by_class_name('Event_Model');
       DB::statement('DELETE FROM tasks WHERE parent_type = ?', [$id]);

   or in pure SQL:

       DELETE t FROM tasks t
       JOIN _type_refs r ON r.id = t.parent_type
       WHERE r.class_name = 'Event_Model';

   Sweep EVERY column declared in any model's $type_ref_columns (plus the
   audit *_by_type columns if an actor model was retired - which
   Rsx_Actor_Model_Abstract forbids for exactly this reason).

3. Then drop the registry debris:

       php artisan rsx:type_refs:prune

4. If you previously wrote compensating code around the silent behavior
   (null checks for phantom class names, try/catch around morphTo reads,
   direct _type_refs queries in cleanup migrations), remove it / switch the
   lookups to find_id_by_class_name().

--------------------------------------------------------------------------------
VERIFICATION
--------------------------------------------------------------------------------

    php artisan rsx:health          -> no "Type References" WARN rows
    php artisan rsx:type_refs:prune -> "nothing to prune" (or lists only
                                       refs you are deliberately keeping)

Every page that reads a polymorphic relation renders; no
"Class name must be a valid object or a string" anywhere in the logs.
