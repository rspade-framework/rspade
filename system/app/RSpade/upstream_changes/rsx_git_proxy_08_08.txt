RSX:GIT - THE GIT PROXY REPLACES THE rsx:clean-THEN-PULL RITUAL
Date: 2026-08-08

SUMMARY
    `php artisan rsx:git <any git command>` now owns every git operation on a
    downstream RSpade app. A Claude Code hook blocks bare `git` and names the
    equivalent, and the old pre-pull guard is removed.

    Everything about the proxy itself self-applies: the script ships in the
    framework-owned bin/ zone, the hook registers itself through the environment
    updates, and the retired guard's registration is deleted for you.

    WHAT YOU MUST DO BY HAND is get the OLD ritual out of your own project:

      1. Any place YOUR repo tells a human or an agent to run
         `rsx:clean` -> `git pull` -> `migrate`. That sequence DEADLOCKS on a live
         box and is now wrong advice. Replace it with `rsx:git pull` -> `migrate`.
      2. Any script, alias, Makefile target, deploy step, or CI job in your repo
         that runs `git pull` / `git merge` / `git reset --hard` / `git checkout`
         against the project working tree.
      3. Any custom Claude Code hook or slash command of yours that wraps `git`.

WHY THIS EXISTS
    Three processes mutate the working tree during any git operation on a live
    RSpade container, and plain git is defended against none of them:

      1. The container's fixperms loop chmods/chowns every newly created file,
         including files inside .git/ (objects, index, lockfiles), racing git's own
         writes. This is also why every clone runs with core.fileMode false.
      2. The JIT manifest rebuild re-applies the class-override pass (.php <->
         .php.upstream renames, use-rewrites, composer autoloader regeneration) on
         ANY web request that touches the manifest - re-dirtying system/ within
         about a second of any clean.
      3. .git/index.lock contention from concurrent status/build processes.

    The consequence: system/ cannot be held clean for the instant a pull or merge
    needs it. The previously documented fix - run `rsx:clean`, then pull - loses
    that race on a box that is actually serving traffic: the churn is back before
    the pull's index write lands. Reported from a live coordinator box where a
    routine commit/pull/merge/push sync deadlocked repeatedly and ended in
    `fatal: stash failed`.

    rsx:git owns the invariant instead: THE APP NEVER SEES OR COMMITS system/
    CHURN, AND TREE-REWRITING OPS RUN QUIESCED.

WHAT rsx:git DOES
    It is a TRANSPARENT proxy. Every subcommand, flag, exit code, stdin, and TTY
    behavior (editors, pagers, interactive `rebase -i` / `add -p`) is git's. Only
    --rsx-* flags are consumed by the wrapper. On top of that:

    status / diff / add
        system/ and every submodule gitlink are excluded with an injected pathspec,
        so GIT produces the output - native color, native pager, byte-clean
        --porcelain. A human `status` prints a one-line stderr footer naming how
        many paths it hid.

    commit
        Staged system/ paths are unstaged first, whatever staged them. `-a` is
        REWRITTEN to an excluding `git add -u` plus a plain commit (pathspecs on
        `git commit` mean "commit ONLY these paths, bypassing the index", which is a
        different operation).

    pull / merge / rebase / cherry-pick / revert / checkout / switch / restore /
    clean / reset --hard / stash pop|apply
        maintenance:enable -> reset system/ to HEAD -> run the op -> rebuild once ->
        maintenance:disable, via an EXIT trap so a failure or Ctrl-C never leaves
        maintenance stuck on. Ops that rewrite nothing (`checkout -b`, `clean -n`,
        `restore --staged`, a plain `reset`) skip the cycle.

    conflicts
        Conflicts inside system/ resolve to the INCOMING framework version and the
        operation is finished for you. A conflict in YOUR files stops with the
        maintenance window LEFT ON - services are down on purpose so you can resolve
        the merge without traffic - and `rsx:maintenance:disable` refuses until the
        merge lands.

    push / fetch / log / show / branch / everything else
        Plain git. log and show are deliberately NOT filtered: they show COMMITS,
        not working-tree churn, and hiding framework-update history would be the
        opposite of helpful.

    Overrides: --rsx-raw (show/stage the true tree including system/),
    --rsx-include-system (deliberately stage a framework edit), --rsx-no-maint (skip
    the service cycle, e.g. when you have already bracketed a batch yourself).

    Full treatment: php artisan rsx:man rsx_git

HOW TO FIND YOUR OWN CALL SITES
    Prose that encodes the old ritual (check your CLAUDE.md, README, runbooks,
    docs/, and any .claude/commands/*):

        grep -rn "rsx:clean" --include="*.md" . | grep -i "pull\|git"

    Scripts and CI that drive the working tree:

        grep -rn -E '\bgit +(pull|merge|rebase|reset|checkout|switch|stash)\b' \
            --include="*.sh" --include="*.yml" --include="*.yaml" \
            --include="Makefile" --include="*.json" . \
            | grep -v '^./system/'

    Read-only git in a script (`git rev-parse`, `git log`, `git describe` for a
    build stamp) does not need converting - it never touches the working tree. The
    ones that matter are the tree-rewriting verbs above, plus `add`/`commit` if any
    script of yours commits on your behalf.

CONVERSION
    Mechanically, prefix the command:

        git pull                     ->  php artisan rsx:git pull
        git add -A                   ->  php artisan rsx:git add -A
        git commit -am "..."         ->  php artisan rsx:git commit -am "..."
        git checkout main            ->  php artisan rsx:git checkout main

    The documented pull sequence becomes:

        php artisan rsx:git pull
        php artisan migrate

    (`migrate` afterwards is unchanged and still required - a pull can bring
    migrations from other environments.)

WHAT CHANGED THAT YOU DO NOT HAVE TO DO
    - system/bin/rsx-git.sh ships in the owned zone; it arrives with this update.
    - system/bin/claude-git-guard.sh is registered as a PreToolUse hook on Bash by
      environment_updates/040_claude_git_guard.sh, augment-only: your existing hooks
      are preserved. The same installer REMOVES the retired pre-pull guard's
      registration (both spellings) - you do not need to edit
      .claude/settings.json.
    - `php artisan rsx:maintenance:disable` gained a conflict guard: it refuses
      while the repository has unmerged paths, and a new --force overrides it. If
      you script a disable somewhere, add --force only if you genuinely mean
      "bring services up over a half-merged tree".
    - `rsx:clean` is unchanged and still does what it always did. It is simply no
      longer the pull ritual.

NOTES
    - In the framework monorepo rsx:git is inert passthrough (there system/ is the
      authored framework source, not a vendored tree) and the redirect hook is never
      installed. This only matters if you also work on the framework itself.
    - KNOWN GAP: an IDE's internal git calls do not go through a shell and cannot be
      intercepted. A stray system/ churn line in your IDE's source-control panel is
      that, not a bug - use rsx:git from the terminal for anything that matters.
    - The proxy is fail-open by design: any internal failure falls through to plain
      git, and a broken maintenance step warns rather than blocking your operation.
      The ONE place it refuses is the integrity gate - it will not silently discard
      hand-made modifications to system/. If you see that refusal, inspect with
      `rsx:framework:verify` and discard deliberately with `rsx:clean --force`.
