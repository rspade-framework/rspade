# rsx/app/frontend/projects — CRUD, following the clients pattern

Follows `rsx/app/frontend/clients/CLAUDE.md` and the app skill `crud-patterns`: `list/` + `view/` + `edit/`, one controller of Ajax endpoints, one datagrid, a dual-`@route` add/edit action. **What differs here:**

- **No `history/`** — the only one of the four CRUD features with no revision-history action or History link (`Project_Model` records revisions; nothing here shows them). No portal subtree, no modals, no SCSS; no `delete`/`restore` (so no delete button and no `Action_Menu` in the sidebar); CSV export only.
- **The datagrid joins `clients`** (`map_sort_column()`: `client` -> `client_name`) and **boots filtered** — `static default_filters = { status: Project_Model.STATUS_ACTIVE }`.
- **A projects-only `subprojects` tab**: the model is self-referencing, and `save()` runs a cycle guard on `parent_project_id` through `Project_Model::self_and_descendant_ids()`.
- **Computed values in the view template** (open tasks, overdue tasks, an `$alert` KPI when any task is overdue) and **two `People_List` mounts** in Overview — the only consumer of that component.
- **Status and priority are enum selects** (`Project_Model.status__enum_select()` / `priority__enum_select()`); a new project defaults to `STATUS_ACTIVE`, so it appears in the list's default view.
- **`save()` checks every value it writes**: the name's length, `start_date`/`due_date` as real `YYYY-MM-DD` dates (`Rsx_Date::is_date()`), a declared status and priority, the budget (below), and each `contacts`/`assigned_users` entry as a record id - anything else is a field error.
- **The budget is the template's worked example of a money column** (`'budget' => ['money' => true]`; `rsx:man money`):
  - **Save**: `Project_Model::money_from_submitted('budget', $params['budget'] ?? null)` reads what was typed (`$1,234.50`, `1234.5`, `(5.00)`) as an exact `Rsx_Money`, a blank as null (no budget - never zero; `0` is stored as 0.00), and refuses an amount larger than the DECIMAL(15,2) column holds (`Project_Model::money_limit('budget')`, 9999999999999.99). A refusal whose `is_input_problem()` is true becomes the field error, with the exception's own message (`This is not an amount of money.`, `An amount of money has at most two decimal places.`, `This amount is outside the range the system can hold.`, `This amount is larger than this field can hold.`); a negative amount is refused with `Budget must be zero or more.`. All before the first write; `Form_Edit` compares the amount exactly, so re-saving the same figure typed differently writes nothing.
  - **Edit form**: `<Money_Input $name="budget" />`, seeded with null (add) or the record's `Rsx_Money` (edit) - never `''`.
  - **View**: `<%= _project.budget %>` prints the formatted amount; "has a budget" is `_project.budget !== null` (an object is always truthy). The Subprojects tab lists each subproject's budget, and its table footer shows the "Total budget" - `project_subprojects()` answers `subprojects_budget` through `sum_money('budget')`, $0.00 for none - and, when the project has a budget, "Unallocated" = `_project.budget.subtract(subprojects_budget)` in a `<Money_Display $negative_red=true>` (negative = over-allocated).
  - **CSV export**: `$project->budget?->to_decimal()` - the exact decimal, an empty cell for none.
  - Tests: `rsx/tests/Project_Budget_Test.php`, `rsx/tests/playwright/project_budget_round_trip.js`.
- **A reference the project already holds is not re-validated on save** - its client, its parent project, and every contact and user already linked - so a project whose linked row was since deleted still saves; `project_form_options` offers such a linked contact or user with its label marked `(deleted)`. A reference the submission adds or changes must name a live record of this site.
- **Pivot-table save**: `save()` syncs `Project_Contact_Model` and `Project_User_Model` inside `Form_Edit::run()`'s transaction and row lock, on the rule "absent key = leave untouched, present-even-empty = replace"; the edit page loads its option lists over Ajax on both add and edit.
- **The edit form's navigation guard follows the form's `'dirty'` event** (on when the user has changed a value - never the load of the record or of the option lists - off when every value is back or the save succeeds), and goes off on the Cancel link (`@click=this.discard_changes`) and in `on_stop()` - the pattern commented in `../contacts/edit/Contacts_Edit_Action.js`. Skill `rspade:navigation-guard`.
- **Borrows two inputs it does not own**: `Client_Selector_Input` (`../contacts/`) and `Ajax_Entity_Select_Input` (`../tasks/`). Also the only edit form using `Wysiwyg_Input` and `Checkbox_Multiselect_Input`.
